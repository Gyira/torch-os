# 薪火OS · Obsidian 插件（2.3.0）

2.3.0 起工作台改为“界面先出、服务后台启动”：插件用自己的 Node 服务（只监听
`127.0.0.1`）直接提供 `frontend/` 静态界面，并把 `/api/*`、`/harness/*`（含
WebSocket）代理到当前库的 Python 后端。打开面板不再等 Python；服务未就绪时先显示
上次读取的只读缓存，并给出具体的失败原因（例如旧编号目录）、重试/查看日志/整理
旧目录入口。启动失败会监听子进程退出并读取本次启动的日志尾部，不再白等 30 秒。
后端日志增加 `PYTHONUTF8`/`PYTHONIOENCODING`，Windows 下中文错误不再乱码。

2.2.3 修正“ChatGPT 显示不出来”的两种表现：①宿主的 webview 只按 `dom-ready` 判定成功，被 DNS 劫持/直连失败时停在空白页却仍报“网页已载入”；②前端只在“内容区可见”的那一帧上报位置，切页或顶栏下拉开合造成的瞬时不可见会让占位文案一直留着。现在：

- 落点域名不是 chatgpt.com / openai.com 就判定为载入失败，收起 guest，把原因写回内容区的卡片（重新载入 / 浏览器打开）；
- 新增设置项“ChatGPT 内嵌浏览器代理（仅本机）”：只对 `persist:torch-chatgpt` 分区 `setProxy`，宿主主会话与 iframe 不受影响，留空跟随系统代理；
- 位置上报带重试与去重，DSH 与 ChatGPT 来回切换不会再卡在占位状态。

2.2.2 新增“与神对话 → ChatGPT / DSH”。ChatGPT 由桌面宿主的 webview 承载在页面内容区域，首次使用需要在该网页中登录。会话使用本机独立分区 `persist:torch-chatgpt`，与外部浏览器的登录状态不自动互通。切换平台保留页面，关闭工作台销毁视图；登录 cookie 由本机 Electron 分区保留。

更新后需要停用再启用“薪火OS”插件，或者重启 Obsidian，仅刷新工作台不能更新宿主桥。普通浏览器版提供外部打开入口。手机 Companion 尚未接入此桌面宿主视图。

实现不注入 ChatGPT 页面脚本，不读取账号凭据，不向 ChatGPT 自动发送个人数据库资料，不启用 Node 集成或 preload。网页认证和验证挑战可能限制内嵌浏览器，可使用工具栏“浏览器打开”。当前自动化验证覆盖平台切换及模拟宿主生命周期，真实 ChatGPT 登录尚未验收。

把整个工作台住进 Obsidian：一个 `薪火OS` 标签页里是产品本体（iframe 内嵌 `?embed=1&panel=1&host=obsidian`），
外加按库隔离的数据目录、自动拉起本地服务、主题跟随与打开任务文档。**免构建**：`main.js` 是手写的
CommonJS 单文件，Obsidian 直接加载。

2.3.0 起界面不再等 Python：插件先用只监听 `127.0.0.1` 的 Node 服务提供
`frontend/` 静态文件（iframe 的 origin 固定为 `http://127.0.0.1:<uiPort>`），
Python 在后台启动；`/api/*` 与 `/harness/*`（含 WebSocket）由同一个服务反向代理。
服务未就绪时常用只读接口回放本机缓存，失败时显示具体原因与处理入口。

## 功能

- 左侧 ribbon 图标 / 命令面板“打开工作台” → 打开 `薪火OS` 视图；再次打开会聚焦已有视图；
- **在哪个库工作，哪个库就是工作区（2026-10-17）**：
  - 插件读取当前库的绝对路径，计算 `vault_id`；
  - 先探测已经存在的、服务同一个库的后端实例；没有就用 `.venv` 的 Python 启动一个
    （`PORT` 从 9168 起自动选空闲端口、`VAULT_DIR=当前库`、`DATA_DIR=当前库/.torch-os`、
    `TORCH_VAULT_SCOPED=1`；8765 留给浏览器/手动模式，两者可同时运行）；
  - 每个库一个实例，各自的 SQLite/索引/记忆/备份互不相通；界面里不再提供“切换工作区”；
  - **仓库路径、Python 路径和实例端口是“这台电脑”的属性**：只保存在本机
    `%LOCALAPPDATA%\torch-os\obsidian-plugin\<vault_id>.json`（macOS/Linux 对应配置目录），
    不写进随库同步的 `data.json`；换设备时会自动查找本机仓库和 `.venv`，不会拿另一台设备的
    绝对路径互相覆盖；
  - 自动查找会看环境变量 `TORCH_REPO_ROOT`、插件里上次的本机路径、用户主目录/桌面/文档、
    Vault 同级目录和常见 `tools` 目录；优先选带 `.venv` 的仓库。找不到时可在设置里手动填写，
    该值也只保存在本机；
  - 启动日志在 `当前库/.torch-os/logs/torch-backend-<port>.log`；子进程退出时会读取
    本次启动新增的日志尾部，并把旧编号目录、依赖缺失、端口占用、数据库锁等翻译成
    可操作的失败提示；
  - **界面服务**：`uiPort` 从 9400 起选空闲端口（避开后端 9168 段），并作为本机设置持久化；
    它只服务当前库的界面和代理，不对外监听；
  - **本地界面缓存**：服务未就绪时先显示上次读取的只读页面数据；缓存在
    `%LOCALAPPDATA%\torch-os\obsidian-plugin\ui-cache\<vault_id>`，不进库、不进网盘，
    设置页可查看占用并一键清除。
- **打开任务文档**：iframe 发 `torch:open-note`（源 + 实例 origin 校验），插件只允许
  `人生路/07_任务与待办/` 下的新任务笔记，或 `_系统/任务（tasks）.md` /
  `_系统/待办（todos）.md`（旧 `00-System` 路径也兼容），
  在新标签页打开；文件不存在时给出提示。
- **打开网页书签（2026-10-28）**：工作台问候语右侧的书签栏发 `torch:open-url`，
  插件校验来源与协议（只放行 http/https）后交给系统默认浏览器（Edge），
  不在 Obsidian 里开内嵌网页——网页版的登录态和免费额度都在浏览器里。
- **1.0 界面能力**：应用内写作、页面角色抽屉（忆灵/苏格拉底等）、提案卡片与忆灵面板
  都在 iframe 内的产品本体里；插件只负责宿主桥、按库实例与主题，不调用模型、不读 Key。
- **主题跟随**：读 Obsidian 的计算样式翻译成产品主题桥的 `--dsw-alias-*` token，
  在 iframe 加载完成、`css-change`（换主题）与 iframe 主动请求时推送；
- **同步感**：视图重新被激活且距上次加载超过 2 分钟时整页重载。

## 安装

用仓库里的脚本（会写进 vault 的 `.obsidian/plugins/torch/` 并预启用）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\install-obsidian-plugin.ps1 -VaultPath "D:\Obsidian\我的知识库"
```

装好后重启 Obsidian（或重载插件）即可在左侧看到图标。设置页可改：仓库路径（仅本机）、
Python 路径（仅本机）、是否自动拉起（界面始终先出，后台启动）、候选服务地址（只有服务的
正是当前库时才会复用，否则另起当前库的实例）。设置页还显示界面端口、后端状态、最近失败
原因，并提供“重新连接”“打开日志”“清除本地界面缓存”。两台设备共用同一个库时，各自第一次
打开会自动查找仓库；也可以点「自动检测」或手动填写一次，路径只留在那台电脑。

## 边界

- 插件只访问本机 `127.0.0.1` 的本地服务与你自己设置的仓库路径；界面服务也只监听回环
  地址，校验 Host/Origin，并拒绝跨来源写操作；不联网、不读模型 Key；
- 随库同步的 `data.json` 只保留 `baseUrl` / `autoStart` 等共享设置；仓库路径、Python 路径、
  `instancePort` / `uiPort` 只存在本机配置目录，不会跨设备同步；
- 本地界面缓存含页面摘要（不含个人设置、正文、AI、媒体），只存本机配置目录，可随时清除；
- 多个库同时打开时各自一个后端进程和一个界面服务；Obsidian 关闭后后端进程可能继续存在，
  下次复用，界面服务随插件卸载关闭；不自动杀后端；
- 手机端不支持（本地服务在电脑上，`isDesktopOnly: true`）。
