## 设计依据

- D1：长期记忆、自我档案与最懂用户的人生导师是核心资产。
- D2：AI 自主更新档案；明确事实与导师推断可区分；对话可纠正；新判断成为当前版本，旧判断保留为成长历史。
- D3：人生导师是独立角色，拥有全局信息读取权限。
- D4：领域角色自主处理所属领域资料，不能因共用网关而自动获得全局信息。
- D5：前端模块与固定资料目录对应，路径统一定义，缺失自动补建。
- D6：工作台聚合高频操作，待办资料归生活运营。
- D7：导师可主动提问，用户可以不回答。
- D8：DSH 是执行与调度底座；“与神对话”用于项目调整、加功能、修 Bug，不等同于人生导师。
- D9：保留品牌、桌面键鼠习惯及已经满意的恋爱/待办流程。

## 分批计划

实施顺序：A0 → B1-R → B3 → B2 → B4a → B4b → B5。保留原 B2/B3/B4 编号，但按依赖和风险调整顺序。每批独立 diff、测试、验收、回退；不一次性重写。

### A0 / P1：契约与文档校准

- 现状 → 建议：当前设计散落于新旧文档 → 固化已确认锚点、标识过时说明、维护目录和角色契约测试。
- 原则与收益：D3/D5/D8，减少后续开发将导师身份、DSH 入口或固定路径改错的机会。
- 范围：当前设计文档、目录契约测试；不改运行时角色提示词。
- 风险与迁移成本：低；无需数据迁移，不改变外部行为或交互习惯。
- 回退：仅撤销本批文档/测试 diff。禁止为统一命名而批量改目录或历史 key。

### B1-R / P0：记忆写入可靠性收尾

- 现状 → 建议：已有保护但并发测试失败 → 先稳定复现，再修复导致访问拒绝的最小路径。
- 原则与收益：D1/D2，已收到的生活记录能可靠持久化，失败不会被报成成功。
- 范围：`memory_store.py`、必要的 `mentor_memory.py` 读写边界及 `test_memory_reliability.py`。
- 规格：保持外部编辑冲突返回 409；不重发模型请求；不自动重提取记忆。若根因修复需要新增文件替换重试，另给次数、时间上限、每次版本复查与失败语义的 B 类方案，不能用重试掩盖冲突。
- 风险：错误重试可能覆盖外部编辑；必须先证实根因。迁移成本低，无格式迁移。
- 验收：16 组线程/8 组进程追加全部保留；冲突、只读、备份失败及进程中断测试通过；验证失败不能改成放宽断言。
- 回退：仅回退本批辅助函数与测试；历史 Markdown 保留。已批准 B1 范围内可继续排错，新增外部行为需单独确认。

### B3 / P0：领域角色的资料边界

- 现状 → 建议：入口和 selector 类型受限，但角色目录归属未统一执行 → 在所有读取及后续写入执行器前应用同一权限映射。
- 原则与收益：D3/D4/D5，医生只收到健康资料，导师能够跨库理解，角色分工有代码保证。
- 范围：`ai_roles.py`、`ai_context.py`、资料选择器及提案执行入口；后续涉及 `dsh/roles/` 时按目录约定单独审改。
- 建议映射：导师读取四库，写档案/导师目录；医生限定健康系统；恋爱角色限定恋爱系统；理财角色限定财务系统；知识导师限定知识库。生活助手等覆盖多入口的角色需在实施规格中逐一列出根目录，不能给隐式全库权限。
- 规格：先校验角色和模式，再校验 selector 及解析后的真实路径，最后读取；recent_notes、汇总与引用也要逐项过滤。前端传入的草稿、选区、路径不能替代授权判断。
- 风险：旧的越域调用可能被拒绝；现有会话历史可能已经含越域信息，不能只过滤新检索。迁移成本中，需标记旧会话或开启新的受限运行会话，旧历史继续供用户查看。
- 验收：直接 note 路径、聚合摘要、目录穿越、链接、历史上下文均不能让领域角色越域；导师仍可读取四库。
- 回退：新策略执行器与旧逻辑保留切换点，不删除历史会话；回退会恢复旧边界行为，需要明确记录。

### B2 / P1：导师会话与草稿隔离

- 现状 → 建议：异步结果写共享状态 → 按 threadId + 请求世代隔离，切换或新建时使旧回调失效。
- 原则与收益：D1/D3/D9，谈话不串线，切换后回来仍能继续表达。
- 范围：`frontend/mentor.js`、`mentor-model.js` 与 UI 回归测试；复用角色抽屉已有模式，不抽象全新的聊天框架。
- 规格：A 会话回复可留在 A 的服务端历史，不能追加到 B；旧 finally 不能解除 B 的 busy；每个会话独立保存页面内草稿；失败不覆盖后续输入；发送键与换行习惯保持。
- 可选交互：等待回复时允许编辑下一条草稿，但当前轮未结束仍不发第二轮；该项明确改变输入习惯，单独确认后启用。
- 风险与成本：低至中；页面刷新不承诺恢复尚未持久化的草稿，无数据库迁移。
- 验收：A→B 切换、新建会话、慢成功/失败、连续点击、中文输入法以及键盘焦点均有针对性测试。
- 回退：按本批前端 diff 回退；后端历史和记忆文件不变。

### B4a / P0：当前判断与成长历史的一致提交

- 现状 → 建议：替代操作依赖两次写入和异常补偿 → 以条目为单位锁定，提交前重查版本，并提供中断后的恢复记录。
- 原则与收益：D1/D2，纠正看法后只有一个当前判断，旧判断仍能追溯。
- 范围：`self_archive.py:supersede_entry`、`mentor_pending.py:accept_pending`；复用现有 entry_id、revision、supersedes，不另造档案格式。
- 规格：先保证旧版可追溯，再发布新版；恢复流程不把未完成的新版和旧版同时当成当前事实；同一操作重复到达只能应用一次。
- 风险与成本：中；需要最小的事务/恢复元数据，放 `.torch-os`，不新增前端模块目录。
- 验收：双请求纠正同一条目、各写入步骤中断、重复提交、历史读取；失败后旧内容可用且恢复行为可解释。
- 回退：关闭新提交入口，处理完未完成操作后回退执行器；保留已生成的新版和历史，不能靠删历史回退。

### B4b / P1：导师自主更新档案

- 现状 → 建议：导师生成待确认卡 → AI 完成理解与校验后直接提交，用户从“本轮更新”查看事实、推断、依据和历史，并通过对话纠正。
- 原则与收益：D1/D2/D3，导师真正承担整理工作，用户无需逐条审批。
- 范围：`ai_roles.py:_archive_pending`、`self_synthesize.py`、`mentor_pending.py`、`frontend/mentor.js`、档案展示模型。角色提示修改作为同批明确审阅项。
- 规格：沿用 fact/inference 等类型；事实保留用户原话/来源，观察保留推断身份。用户改变看法时建立替代链，不修改旧版正文。成功只显示非阻塞“已更新 N 项”，不强制切页；部分成功逐项说明，失败不能显示“已记下”。
- 风险与成本：高；推断误写为事实、重复应用和多文件部分成功需要处理。先限定导师的档案/记忆自主写，领域角色自主行动另批接入。
- 迁移：保留旧待确认卡，不批量自动批准；新请求使用新执行模式，已有历史可读。
- 验收：事实/推断分离、对话纠正、成长历史、幂等、部分失败与开关回退；禁止以“全局读取”推导跨域任意写入。
- 回退：切回旧待确认执行模式；已自动写入的条目保留，可通过版本链纠正。回退开关不删除真实记忆。

### B5 / P2：每日提问与更新反馈

- 现状 → 建议：普通回答和拟答采纳走不同归档路径 → 统一进入导师理解/校验链，来源类型清楚标注。
- 原则与收益：D2/D7/D9，回答能够沉淀，跳过不会成为负担。
- 范围：`mentor_questions.py`、导师提问视图及更新反馈；沿用现有“跳过/不再问”。
- 规格：不回答不生成答案；未采纳拟答不当作用户事实；跳过不触发补答弹窗。先完成回答记忆保存，再处理档案更新；失败分开反馈。状态过渡 180–220ms，减少动态效果时取消位移；完成不抢焦点。
- 风险与成本：中；要防止把模型拟答当成自述。旧问题保留原状态，不批量重新回答。
- 验收：跳过/不再问、跨日、保存失败、重复提交、键盘操作、读屏状态通知与 reduced-motion。
- 回退：关闭新的归档接线，保留问答和更新日志。
