# 存储兼容与同步协议决策（2026-11-14）

状态：P2a 与 S1a 可测试基础。不是完整存储迁移或可发布的同步插件。

## 存储与身份

`backend/app/storage_layout.py` 是唯一的新路径契约入口，构造/加载不创建目录、不移动数据。legacy 模式精确保留 P1 的路径哈希、快照数据库文件名和资料包目录；已有客户端使用的 health.vault_id 保持原行为。新增 health.workspace_id 只读解析共享身份，未初始化旧库为 null。

split 模式要求五个绝对根 notes/state/archive/cache/exports，任意两根不能重叠，拒绝路径中的链接和目录联接。设备配置记录本机路径，不作为普通同步文件。共享 `_Torch/工作区.md` 只包含 UUID 与 storage_version，不含本机绝对路径。损坏、身份不匹配和未知版本均失败，禁止静默换库。

初始化函数只能用于空库；旧库建立身份与路径映射必须走后续迁移流程。库被复制为独立工作区时需显式重建身份；仅移动/同库恢复保留 workspace_id。device_id、业务消费者资格和路径旧身份 alias 尚未整合入插件实例发现。

`ShareStore` 和资料包路由接受显式布局，可在隔离测试库中写入独立 state/exports。整个 application 当前仍采用 legacy 布局，不提供全局启用 split 的环境变量；LovePaths、备份/恢复及其他业务路径未适配之前不能把系统整体切换到 split。

`scripts/plan_storage_split.py` 仅输出不可执行候选分类。它不会搬文件或改引用，业务 DB、未知资源、配置和凭据均标为待审阅。目标需为空且不与源库重叠；报告不能放进源库或目标目录。它还不是完整迁移预览：引用审计、空间预算、SQLite 快照、独有记录核对、备份恢复和切换回滚都留待下一切片。

## 同步核心

`companion/core/protocol.ts` 不依赖 Node、Obsidian 或百度运行时；使用 Web Crypto SHA-256，保持原始 UTF-8 内容字节，无 mtime 仲裁。Node 24 可用 `node --experimental-strip-types --test companion/tests/protocol.test.ts` 运行合成测试；这不是安卓支持证明。

- revision 记录明确的 workspace/account/remoteRoot/protocol 绑定，以及 file/device/operation 身份、父版本、put/delete 和内容哈希。
- revision 的规范化哈希作为提交 ID；上传内容并回读校验成功后才能发布提交。绑定变化必须重新配对。
- 汇集不可变提交，以祖先关系识别有效分支，不依赖一个可覆盖的“最新 manifest”。输入乱序允许；缺失祖先的记录保持 pending。
- 同一 file 有不同内容的并发头，返回 conflict_preserve_all。相同内容但不同因果头，要求显式 join 提交；不丢弃分支历史。
- 删除必须是带父版本的显式提交；空远端没有删除语义。存在不完整历史、网络异常或对象校验失败时不生成可执行删除计划。
- 冲突解决生成一个以双方版本为父的新提交，原始内容继续保留。
- 扫描历史只读取版本元数据；正文只校验当前/冲突分支头，不全量下载历史正文。历史恢复时再单独读取和核验所选版本内容。
- 设备/操作 ID 重放但内容不同会被检测并停止该轮；未来适配器必须把本地 operation_id 持久化，并保证不可变对象/提交路径不能覆盖别人的操作。

Transport 接口是约束，不代表百度 API 天然具备不可变写入或原子 CAS。测试使用内存不可变存储，真实百度适配需单独验证发布语义、列表完整性、分页、延迟和响应丢失。

首切片尚无本地文件物化器、持久操作日志、设备身份安全存储、路径/file_id 映射、重命名、批量删除熔断、加密或历史压缩；第二切片进展见下文。assertLocalUnchanged 只是规划前后的检查函数，不声称解决真实文件写入的竞争窗口；后续写入适配须保留被覆盖版本、使用恢复日志并验证编辑器行为。

### 2026-11-14 第二切片补充

新增 `DeviceRegistry`：注册表只保存在显式传入的本机目录，SQLite 事务保证并发初始化返回同一个 device_id；不同本机目录生成不同 ID。bind 是显式操作，验证 notes 中的 workspace_id，再登记新路径和旧路径哈希 alias。lookup 不创建未知注册表；已注册身份文件丢失或错配时拒绝返回有效绑定。尚未接入现有桌面插件的端口与进程复用流程。复制整个设备注册表会复制 device_id，恢复到新设备时的显式轮换和旧设备撤销仍待实现。

新增 `core/journal.ts`：保存不可变操作记录（原文备份、新正文、绑定、预期哈希、提交 ID 与全记录校验和），在远端/本地完成后分别写独立回执。记录先持久化，再执行副作用；远端成功但响应丢失可重试同一提交，本地写完但回执未写可按当前正文恢复。检测到新编辑则保留并返回冲突；不清理操作记录或备份。

`tests/file-journal.ts` 提供实际磁盘测试日志，完整临时文件刷盘后通过独占硬链接发布；旧记录只允许逐字相同重试。测试不依赖同一 JS 实例保存状态，可重新打开目录恢复。覆盖的是进程中断/响应丢失，不声称已经完成所有文件系统的断电耐久性验证。

applyPending 的 LocalFiles 接口要求原子比较并写入；本轮测试用可控的原子编辑模型，不是普通 `readBinary` 后 `writeBinary`。Android/Obsidian 尚无经验证的实际实现。实际适配若不能提供原子条件替换，必须设计保留全部有效版本的受保护物化方案，不能直接照搬测试模型并宣称无竞争。

新增 `storage_audit.py`，复用现有 vault_links 的只读扫描器识别 Markdown/wiki 引用，输出唯一匹配、歧义、缺失与未覆盖类型，不改正文、不读取 SQLite。Canvas、HTML/引用式/复杂括号链接和业务表路径仍需补审；safe_to_migrate 固定为 false。已解析到附件只说明原库内可定位，不授权迁出它。

第一版 file_id 与 Markdown 业务 note_id 分离：不批量改旧 frontmatter。具体首次导入、同名独立创建、大小写/Unicode 归一化碰撞和重命名映射在物化器切片落实；目前核心只处理不含路径的稳定 file 标识。

上游参考提交仍固定在设计文档记录的版本；本轮没有复制其代码、创建远程 fork 或发布插件。百度传输整合时保留上游许可证和来源，并使用独立的 Companion 插件 ID。

## 回退和下一切片

### 2026-11-15：真实磁盘落盘与百度只读适配

新增 `core/materialize.ts`，专门用于不具备原子 CAS 的环境，不替换旧 LocalFiles 的严格接口。策略有意保守：同内容可恢复回执；缺失且预期为新增的笔记通过独占发布创建；已有笔记的任何远端变更均保留为 state 中的候选版本，普通单端更新也返回 update_requires_review。删改冲突或新建同名冲突返回 conflict_preserved；删除请求返回 delete_requires_review，不删除原文件。外部已删除的旧笔记不会被更新操作自动复活。

`node/files.ts` 将原测试磁盘日志升级为独立桌面适配，并增加 FileNotes：检查路径、目录联接/符号链接、笔记根存在性和读取预算；临时文件完整写入并刷盘，再通过独占硬链接发布，绝不覆盖已有文件。journal 必须在 notes 之外。首次落盘后进程中断、回执缺失、并发同名创建和删除请求均在真实临时文件上测试。不能据此声称具备安卓文件能力或抗恶意并发文件系统替换；硬链接不可用时安全失败，不退回覆盖写入。

候选文件位于 `candidates/<commit-id>.md` 的本机日志目录，不进入笔记检索或滴答业务解析。其原始内容未被重写。此阶段尚无审阅 UI、自动替换已有笔记、实际删除、重命名/路径映射或监听事件抑制，故不能宣称可替换日常同步。

新增 `baidu/reader.ts` 和 `http.ts`：受限 XPan list 请求、完整分页、令牌刷新后重新生成 URL、响应体预算/超时、禁重定向、固定主机和错误脱敏。目录不存在、未知响应、重复分页都抛错，不变成空目录。仅提供只读列举，不提供账号申请、OAuth UI、上传、下载、加密或完整 Transport。测试使用模拟 HTTP/令牌；没有访问真实百度账号。上游 API 使用参考及 MIT 说明已加入 third-party。

TypeScript 严格检查现覆盖 core、node、baidu 和 tests；增加固定 @types/node 开发依赖。仓库 check_all 纳入这两项 Companion 检查，防止只跑 Python 就漏掉同步模块。

legacy 路径不变，生产库没有增加身份文件或更换数据根。新模块可在不启用 split 的情况下保留。已创建的测试目录与报告不代表迁移完成。
