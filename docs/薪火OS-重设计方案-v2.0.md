- 状态：设计定稿，Phase 1–5 已实施（2026-10-22；Phase 5 为保守清理）
- 日期：2026-10-20（实施更新 2026-10-22）

- 范围：除工作台外，全部模块重新设计；工作台 UI/DOM/交互/视觉保持不动

## 1. 背景与目标

现状问题：

- 现有「数字分身」「第二大脑」两套模块与设计书的四库结构不对应，功能面广但没有一条清晰主线。
- 存在多套数据源：日记有 Markdown 与 SQLite 两套，任务有 Markdown 与 SQLite 两套，身体/习惯只在 SQLite，无法做到「所有东西写回数据库」。
- 用户明确：除工作台外，现有模块都不满意，可以全部重做；有价值的后端逻辑复用。

重设计目标：

1. **保留工作台**：现有工作台页面、任务/日历/习惯/四象限/回收站、横幅、天气、黄历的 DOM、交互、视觉全部不动。
2. **四库成为产品骨架**：人生路、自我档案、生活运营、知识库，与设计书的 Obsidian 目录一一对应。
3. **Markdown 是本体**：所有个人内容写回 Vault；SQLite 只做索引、投影、提案和审计。
4. **好看、安静、可长期使用**：编辑型知识工作台，而不是卡片仪表盘。
5. **迁移可预览、可回滚**：先预览后执行，迁移前强制备份。

## 2. 设计原则

1. 工作台不动的边界：不改 DOM、ID、CSS、交互；允许底层数据路径迁移（日记、身份），以及指向已删除模块的文案修正。
2. 四库是唯一合法个人内容结构；`00-System` 是工作台系统区，不属于四库，也不是用户可以随手放笔记的地方。
3. 一个数据只有一个权威源；SQLite 投影随时可删可重建。
4. 先提议、后执行：AI 与迁移都只生成提案，用户确认后由后端执行。
5. 不删除、不覆盖：移动前查重，冲突就停下来报告。
6. 空状态必须有解释和下一步动作；高频操作要快，低频仪式要有仪式感。
7. 视觉：纸墨质感 + 赤陶品牌色，四库各有强调色，但只在四库页面生效，不污染工作台。

## 4. 四库产品设计

### 4.1 人生路 —— 管过程

一句话：**把每天过成可回看的成长线索。**

总览页：

- 顶部：今天日期、连续记录天数、「今日三件事」状态（日记是否已写、习惯完成 x/y、今日任务 x/y）；任务数据只读自工作台 API，不新建任务系统。
- 快速入口：`写今日日记`、`记一条反思`、`记一条心得`。
- 仪式卡：今日日记、本周复盘、本月复盘；未完成时显示「还差什么」，完成后显示一句摘要。
- 时间流：最近 7 天的日记/反思/心得，按天排列，点击进详情。
- 目标与计划：年度/季度/月度目标卡（进度来自笔记 frontmatter 或手动百分比）、进行中的项目计划。
- 工作复盘：最近项目复盘、会议收获、踩坑记录。

关键交互：

- 写日记 → 打开现有日记生成接口（工作台同一份数据），生成骨架后在 Obsidian 编辑。
- 周复盘 → 读取最近 7 天日记/反思，生成确定性骨架（主题词、情绪词、待提炼项），一期不调用模型。
- 「提炼为原则」→ 从日记/反思详情发起，跳转自我档案新建沉淀笔记，原文用双链引用。

空状态：`还没有今天的记录` + 「写今天的日记」；文案解释「这里记录过程，不追求完整」。

视觉：赤陶强调色；时间线用竖线 + 日期间隔，标题用衬线。

### 4.2 自我档案 —— 管我是谁

一句话：**把经历沉淀成「我是谁」。**

总览页：

- 身份卡：姓名、座右铭、三观关键词、最近更新；数据来自迁移后的 `身份（identity）.md`，工作台横幅继续复用同一份。
- 记忆长河：重要记忆/人生节点的时间轴。
- 灵感闪念：最近想法卡片。
- 关系地图：重要关系与边界（列表 + 标签，不做复杂图谱）。
- 意义与目标：人生愿景、长期方向。
- 沉淀与创作：最近提炼的原则、工作方法、职业原则。

关键交互：

- 记录灵感 → 快速捕获，直接写入 `03_想法与灵感`。
- 添加记忆 → 日期 + 故事 + 意义，一篇笔记。
- 提炼原则 → 从任意日记/反思/心得发起，目标章节为 `06_沉淀与创作`。
- 详情页显示「来源」双链，形成「经历 → 沉淀」的回溯。

空状态：`这份档案还在生长` + 「写下一条此刻的想法」。

视觉：黛青强调色；详情页像书页，正文最大宽度 72ch，衬线标题。

### 4.3 生活运营 —— 管数据

一句话：**把身体、钱、事务照顾好，不让它们占用注意力。**

总览页：

- 健康卡：最新体重、7/30 天趋势 sparkline、睡眠/运动最近数据。
- 财务卡：本月收入、支出、结余、分类占比条。
- 医疗卡：下次体检/用药提醒。
- 事务卡：证件到期、待办事务。

章节页：

- 健康与体重：月度表格，行内新增/编辑；趋势图纯 SVG。
- 财富与记账：月度账目表，类型（收入/支出）、金额、分类、账户、备注；月度汇总与分类占比。
- 体检与医疗：一次事件一篇笔记，支持附件与复查日期。
- 证件与事务：证件/合同/保险条目，到期提醒。

数据形态：**月度 Markdown 表 + SQLite 投影**。一个月的记录一篇笔记，行有稳定 `row_id`；SQLite 只做统计缓存，可随时从 Markdown 重建。Obsidian 里可以直接看、直接改。

空状态：`这个月还没有数据` + 「记第一笔」/「记第一次体重」。

视觉：苔绿强调色；大数字 + 细线表格，图表克制，不做花哨仪表盘。

### 4.4 知识库 —— 管可复用知识

一句话：**先接住，再提炼，最后变成能用的东西。**

总览页：

- 收件箱卡：待分流数量、最近 3 条、「去整理」。
- 最近概念卡、正在读/学、常用方法、最近输出。
- 主题入口：按标签/主题聚合的横向卡片。

章节页：

- 收件箱：先接住。每条至少记：来源、原话/截图、我的理解、待归类。
- 主题笔记、读书笔记、课程笔记、概念卡片、方法库、输出与作品：列表 + 详情，支持双链与来源。

关键交互：

- 快速收藏：来源链接/标题 + 摘录 + 我的理解 → 写入 `03_知识库/00_收件箱`，标记 `#待分流`。
- 整理收件箱：选择条目 → 显示确定性分类建议（二期加 AI）→ 用户确认 → 移动到目标章节。
- 新建概念卡/方法卡：按章节模板生成 frontmatter 与正文骨架。
- 全局搜索：标题、正文、标签、来源；结果带章节与引用片段。

空状态：`收件箱是空的，挺好` + 「收藏第一条」。

视觉：靛蓝强调色；索引卡式网格，搜索框常驻，详情页突出「我的理解」。

## 5. 跨库能力

1. **全局快速捕获**：顶部导航右侧 `＋ 记一条`；标题、正文、来源、类型；默认进收件箱；显示「建议去处」但必须用户确认。
2. **四问归档助手**：按设计书决策树做确定性向导：结构化数据？→ 可复用知识？→ 关于我是谁？→ 否则收件箱。每一步给出理由与候选目录。
3. **全局搜索**：跨四库全文检索，结果带章节、日期、摘要；回答「我什么时候想过/记过……」时只引用原文，不编造。
4. **周复盘骨架**：读取最近 7 天日记与反思，生成骨架（本周输入、行动、情绪关键词、待提炼项）；一期确定性生成，二期可模型润色。
5. **薪火管家（二期）**：收件箱分流建议、沉淀建议、健康检查、带引用问答；只提议、不执行；执行前必须确认，所有操作写审计。
6. **设置 → 库结构与迁移**：布局状态、迁移预览、备份并迁移、回滚、迁移报告。

### 6.2 笔记 frontmatter

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 新笔记必填 | UUID，稳定身份；旧笔记可缺失，用路径身份 |
| `type` | 是 | 见枚举 |
| `title` | 是 | 标题 |
| `created` / `updated` | created 必填 | ISO 时间 |
| `date` | 视类型 | 日记、复盘、体检等事件日期 |
| `pillar` / `chapter` | 是 | `life`/`self`/`ops`/`knowledge` + 章节 key |
| `status` | 是 | `inbox`/`active`/`archived`/`done` |
| `tags` | 否 | 字符串数组 |
| `source` | 否 | 链接、书名、课程 |
| `aliases` / `related` | 否 | Obsidian 别名与关联 |
| `privacy` | 否 | 默认 `personal` |
| `memory` | 否 | 只有 `true` 才允许生成「沉淀候选」 |

`type` 枚举：`journal`、`reflection`、`insight`、`weekly_review`、`monthly_review`、`goal`、`plan`、`habit_definition`、`habit_log`、`value`、`memory`、`idea`、`relationship`、`meaning`、`principle`、`inbox`、`topic`、`reading`、`course`、`concept`、`method`、`output`、`health_month`、`finance_month`、`medical`、`document`。

命名规则沿用设计书：日记 `YYYY-MM-DD.md`，周复盘 `YYYY-Www.md`，概念卡用概念名，方法用「动词+对象+方法」，禁止空格与非法字符；中文标题保留，文件名做安全化处理。

### 6.3 结构化数据

- 习惯定义：`00_人生路/06_目标与计划/04_习惯追踪/习惯定义.md`，表格列 `id/名称/触发提示/最低行动/开始日期/计划日/状态`。
- 习惯打卡：同目录 `YYYY-MM_打卡.md`，列 `日期/习惯id/状态/备注`；缺行 = 未记录。
- 健康：`02_生活运营/01_健康与体重/YYYY-MM.md`，`type: health_month`，列 `row_id/日期/体重kg/睡眠min/运动min/备注`。
- 财务：`02_生活运营/02_财富与记账/YYYY-MM.md`，`type: finance_month`，列 `row_id/日期/类型/金额/分类/账户/备注`。
- 医疗/证件：一次事件一篇笔记。
- SQLite 投影表保留，增加 `source_path/source_row/source_revision`；读取时发现 Markdown 更新就重建投影。

### 6.4 唯一权威源

| 数据 | 权威源 | SQLite 角色 |
|---|---|---|
| 日记 | `00_人生路/01_日记/*.md` | 退役 `journal_entries` 读取 |
| 习惯 | Markdown 定义 + 打卡表 | 统计投影 |
| 体重/账目 | 月度 Markdown 表 | 投影 |
| 目标/计划 | Markdown 笔记 | 仅索引 |
| 任务/待办 | `00-System/**` | 工作台现有逻辑不变 |
| 身份/横幅 | `01_自我档案/01_内核与三观/身份（identity）.md` | 无 |

### 6.5 索引策略

不再用「排除目录」一刀切，统一为三档：

- `skip`：`.obsidian`、`.git`、`.claude*`、`.torch-os`、`00-System`、templates、`relationship*`、Apex dashboard。
- `document_only`：四库中绝大多数笔记，可搜索，不生成记忆候选。
- `memory_eligible`：`01_自我档案/**`，以及人生路中显式 `memory: true` 的反思/心得/复盘。

这样体重表、账目表、日记不会被误抽成「记忆事实」；索引、活动页、审计共用同一判断。

### 7.3 迁移流程

1. 只读盘点：扫描全库、读 frontmatter、算哈希、记录链接。
2. 生成预览：源 → 目标、理由、冲突、受影响链接；给出 `plan_hash`。
3. 用户确认：设置页表格 + 输入确认；此时不写任何文件。
4. 强制备份：现有 `create_backup` + `verify_backup`，备份验证失败就停止。
5. 执行：创建四库目录 → 逐条原子移动 → 每步写 `journal.jsonl` → 崩溃可 resume/rollback。
6. 链接改写：统一改写 wiki link 与相对链接；保留 alias、`#heading`、CRLF/BOM；跳过代码块、URL、Apex 文件。
7. 索引：`remap_documents` 保留文档身份，再增量扫描；重建链接表。
8. 标记与报告：`.torch-os/layout.json` 写 `pillars-v1`；报告写 `00-System/迁移记录/<run_id>.md` 与 `.torch-os/migrations/<run_id>/report.json`。
9. 验证：哈希一致、源路径消失、4 篇日记可读、工作台任务/习惯/日历/回收站正常、滴答 47 条不变、Apex dashboard 正常。
10. 回滚：`rollback_run(run_id)` 反向移动与反向链接改写；灾难时从已验证备份恢复。

### 7.4 边界

- 目标已存在且 hash 相同：视为已迁移跳过；hash 不同：停止报告，不覆盖。
- Windows 大小写冲突、NFC/NFD、路径过长、文件被占用：预检阶段全部拦截。
- 孤儿附件只报告不移动；空旧目录不删除。

## 8. 视觉设计

### 8.1 方向

「纸墨四库」：暖白纸张、深墨文字、赤陶品牌色；四库各有一个低饱和强调色。工作台保持原样，四库页面更编辑化、更留白、更少阴影卡片。

### 8.2 色彩与字体

新增 token（明暗两套必须同批定义，沿用现有 token 测试）：

- 人生路：赤陶 `#a44d2c` / 暗色 `#e9ac8a`
- 自我档案：黛青 `#6f5a8a` / 暗色 `#c3b0dd`
- 生活运营：苔绿 `#4f7a63` / 暗色 `#9ecbb4`

字体：

### 8.3 布局与组件

- 章节轨：竖向列表，当前项左侧 2px 强调色；移动端横向 chips。
- 条目列表：行高 56–72px，标题 + 一行摘要 + 日期/标签；悬停轻微底色，不做卡片堆叠。
- 详情：正文最大宽度 72ch，行高 1.75；元信息在上，反向链接在下。
- 捕获对话框：一个输入框 + 去向预览 + 「先放收件箱」默认。
- 数据表：细线、无斑马纹、数字右对齐；sparkline 用内联 SVG。
- 空状态：一句解释 + 一个主按钮 + 一条示例，不用插图堆砌。
- 动效：140–180ms 淡入/位移 4–6px；遵循 `prefers-reduced-motion`。

### 8.4 可访问性与主题

- 只用 `--p-*` token；新样式放 `pillar.css`，全部选择器以 `.pillar-*` 或 `[data-pillar]` 限定，避免污染工作台。
- 明暗主题、Obsidian 宿主 token、键盘焦点、`aria-current`、`role="status"`、对话框焦点恢复沿用现有约定。
- 四库页面不引入外部字体、图标库或图表库。
