# 日记闭环（Daily Review）设计 · v1

> 2026-10-28 · 起因：日记目录里 11 篇全是 623 字节的空模板，另有 `_旧版/` 残留。
> 本文回答两件事：**为什么会长出空模板**，以及**怎么把它改成一个真正的闭环**。

## 0. 一句话

把「写日记」从一个 49 行的空表格，改成一条每天 3–10 分钟的闭环：
**盘点事实 → 3 个问题 → 你的一段话 → 一篇干净的日记 → 一条回流**。

## 1. 空模板是谁写出来的

不是 Obsidian，是应用自己：

1. 打开工作台 → `frontend/workbench.js:188-198` 发现 `daily_note_exists=false`
   → 静默 POST `/api/todos/daily/sync`；
2. 后端 `backend/app/todo_note.py:395-419` `ensure_daily_section()` 发现文件不存在
   → `render_skeleton()` 渲染 49 行模板 + 追加 `## 每日必做` → 落盘 623 字节；
3. 结果：只要某天打开过工作台，那天就多一篇「一个字都没写」的日记。

这条写路径与 2026-10-26 定的「四库只读」（`docs/DEPRECATIONS.md:25-39`）直接冲突，
是遗留写入口。**不堵住它，清理多少次都会再长出来。**

`_旧版/02-Life/` 是迁移残留：`backend/app/vault_layout.py:127` 把 `_旧版` 列为跳过目录，
但从未清理；里面 4 篇与主目录同名同日、内容完全相同。

## 2. 设计原则（后面所有取舍都从这来）

| # | 原则 | 反例（现在的问题） |
|---|---|---|
| P1 | **模板是提问清单，不是文档骨架** | 49 行固定段落，没写就是 `-` 和 `____` |
| P2 | **事实由程序写，感受由你写**；AI 只整理，不代写 | 没有生成，全靠手填 |
| P3 | **一天一篇、一个文件、一份权威**；两个入口共用同一份数据 | 模板和对话若各存一份必然分裂 |
| P4 | **不评分、不对比、不追责** | 空模板本身就是一种无声的责备 |
| P5 | **无模型也能用**：确定性有降级 | 一旦模型不可用整条链路就断 |

P1 是这次改动的核心：只要「模板 = 文档骨架」，空段落就一定会出现；
把模板降级成「问什么」，空段落就不存在——**没写的段落根本不生成**。

## 3. 数据：现在真的能自动知道什么

| 数据源 | 能回答 | 代码位置 |
|---|---|---|
| 任务（一任务一笔记） | 今天到期、已完成、逾期几天 | `backend/app/task_reports.py:24-39` |
| 待办（todos.md） | 今天该做、做完了哪些 | `backend/app/todo_note.py:198-204` |
| 每日必做 | 今天勾了几个 | `backend/app/todo_note.py:376` |
| 习惯 | 打卡、连续天数 | `backend/app/habit_markdown.py:39`（⚠️ 本库目前没有习惯数据） |
| 足迹 | 今天改过哪些 `.md`、几点改的 | `backend/app/activity.py:27-67` |
| dsh 会话 | 今天在对话里聊了什么（收件箱会话笔记） | `backend/app/workbench.py:171-197` |
| 提问队列 | 已经攒着、还没问出口的问题 | `backend/app/questions.py:204-257` |
| 现成聚合 | 上面大半已经拼好了 | `backend/app/workbench.py:200-215` `draft_parts()` |

**拿不到的**（必须诚实）：读了什么书、手机用了多久、线下干了什么、你此刻的情绪。
所以第一版只做「线索级」纪要——「你今天动过这 6 篇笔记、完成 1 件、还挂 2 件」，
不做「AI 知道你一天干了什么」的叙事。

> 现状注记（2026-10-28 实测）：任务只有 3 条（背单词 10-22、恋爱八字倒计时润色 10-26 已逾期，
> 考研规划未设期）；`04_习惯追踪/` 是空目录；`待办（todos）.md` 不存在，每日必做主清单为空。
> 也就是说：**「习惯没打卡」的追问现在不会触发，第一版只能靠任务 + 足迹。**
> 这不是数据没接上，是这部分行为还没被记录——先决定「你的习惯到底记在哪」，再谈追问。

## 4. 成品长什么样

```markdown
---
type: journal
date: 2026-10-28
mode: conversation        # conversation | template
status: sealed            # draft | sealed
mood: 清醒
energy: 3
weather: 晴
summary: 把日记从填表改成对话，先清掉 15 个空壳
tags: [日记]
---

# 10月28日 · 周三

> [!quote] 今天的一句话
> 空模板不是我没毅力，是工具替我写了半篇废话。

## 今天做了什么
- 完成 1 件：值班日历显示当天值乘车次
- 还挂着 2 件：背单词（10-22 到期）、恋爱八字倒计时润色（10-26）
- 动过 6 篇笔记：[[考研规划文档]]、[[八字速查卡]] …

## 我想说的
（你回答的三段，整理成第一人称；没回答就没有这一段）

## 明天的一步
- 背单词：先只背 20 个，别定 100 个
```

规则：

- **只有写过的段落才存在**；`今天做了什么` 由程序生成，其余段落来自对话或手写；
- `summary` 一行，供列表、周复盘、检索使用；
- 正文不出现 `____`、不出现空 `-`、不出现「每日必做」清单（清单回工作台）；
- 保底 6 行也是完整的一篇（只有日期 + 一句 + 明天一步）。

## 5. 闭环七步

```
① 盘点   程序读任务/待办/习惯/足迹 → facts（0 成本，永远可用）
   ↓
② 提问   规则候选 → 模型挑 3 条、改写成一句话（失败就用规则原文）
   ↓
③ 回答   对话式：聊；模板式：卡片逐条填
   ↓
④ 生成   模型把「事实 + 你的回答」写成第一人称正文（无模型则拼装）
   ↓
⑤ 预览   你看一遍，改字、删段、选一句当 summary
   ↓
⑥ 写入   唯一写入口：只写当天这篇，带备份 + revision 校验
   ↓
⑦ 回流   1 条反思/心得候选 → 身份待确认或反思库；周复盘读 7 篇
```

## 6. 提问引擎

**候选由规则产出**（每条都带证据，可追溯）：

| 触发 | 证据 | 问题的形状 |
|---|---|---|
| 任务逾期 ≥3 天 | 任务笔记的日期 | 「背单词从 10-22 挂到现在。还要做，还是先拿掉？」 |
| 习惯连续 3 天没打卡 | 打卡文件 | 「是没顾上，还是这个习惯现在不现实？」 |
| 连续 3 天没写日记 | 日记目录 | 「最近是不是太满？」（不质问） |
| 今天改过某篇重要笔记 | 足迹 mtime | 「你下午改了《考研规划》，是在调方向吗？」 |
| 昨天写了「明天做 X」，今天没动 | 昨天日记的「明天的一步」 | 「X 没动，要不要拆成 15 分钟的一步？」 |
| 目标笔记 30 天没动 | 目标笔记 mtime | 「这个目标还算数吗？」 |
| 某个维度一周没提 | 日记全文 | 「这一周没提过身体，有什么吗？」 |

**模型只做两件事**：从候选里选 3 条、改写成像人问的一句话。它不发明事实、不改证据。

**导师规则**（写进 prompt，不靠语气碰运气）：

1. 先描述，后提问，不评价；
2. 一天最多 3 问；同一个缺口一周只问一次；
3. 每个问题必须挂一个事实（时间 / 路径 / 次数）；
4. 建议只给一条，且是「明天 15 分钟内能做完的一步」；
5. 「为什么没做」最多问一次；第二次改成「要不要把它从清单里拿掉？」——**允许放弃，才是亦师亦友**；
6. 不用「你应该」「建议你」，用「要不要」「我猜」。

## 7. 两个入口，一套引擎

| | A 对话式 | B 模板式 |
|---|---|---|
| 场景 | 有情绪、有想法、想被追问 | 忙、只想记两句 |
| 时长 | 5–10 分钟 | 2 分钟 |
| 形态 | 聊天面板，AI 先开口 | 卡片：3 个问题 + 自由写 |
| 落盘 | 同一篇日记 | 同一篇日记 |

两者调用同一个 `compose()`（事实 + 回答 → Markdown），区别只在「回答怎么来」。

对话式入口有两个选项（第 13 节待定）：

- **先做 dsh skill（推荐）**：dsh 已经能读四库（MCP 只读工具）、已经有人格规则（`dsh/skills/torch-mentor`），
  新增一个 `daily-review` skill 就能「盘点 → 问 3 句 → 写回当天日记」。应用只需要一个「聊着写」的入口
  和「今日盘点」卡片。工期 ≈ 1 天，且不重建人格。
- **后做应用内面板**：体验连贯（不用跳窗口），但要重新实现模型调用、上下文、文件写入与降级，
  工期 ≈ 2 天；等 dsh 版跑顺、确认每天都用之后再投入。

## 8. 写入协议（唯一破例）

四库只读是定过的原则，日记要闭环就必须开一个**最小**的口子：

- 只允许写 `00_人生路/01_日记/YYYY-MM-DD.md`，且只能是**当天**；
- 只允许「新建」或「替换受管区块」，保留用户在受管区块外手写的任何内容；
- 必须 `confirm=true`，写前备份到 `.torch-os/backups/`；
- 带 revision/sha 校验，文件在预览后被改过就 409，不覆盖；
- 审计只记路径、字符数、时间，不记正文。

## 9. 接口

```text
GET  /api/journal/digest?day=      确定性盘点（facts + 人话摘要）
GET  /api/journal/review?day=      复盘会话状态（草稿/已封存）
POST /api/journal/questions        生成 3 个问题（带 why/evidence）
POST /api/journal/compose          事实 + 回答 → Markdown 草稿
POST /api/journal/write            确认写入（confirm + revision）
POST /api/journal/seal             封存：删空段、补 summary、写回流候选
```

状态存 `.torch-os/journal/YYYY-MM-DD.json`（digest、questions、answers、draft、revision），
日记文件里只放成品。

## 10. 界面

- **人生路 · 今日卡**：`今天有 6 条线索 · 3 个问题`，两个按钮「聊着写」「填一下」；
- **工作台 21:30**：现有 evening 报告（`scheduler.py:37` 默认 21:30）改成一句邀请，
  不写也不追责，第二天不再提；
- **阅读态**：日期小标题 + summary 引用块 + 段间细线，暗色主题同一套；
- **列表**：`已封存` 与 `草稿` 用不同圆点；没有文件的日期显示「未写」，不再生成空壳。

## 11. 分期

| 期 | 内容 | 工期 | 验收 |
|---|---|---|---|
| P0 | 清空壳（已完成）+ 堵住自动建文件 | 0.5 天 | 打开工作台不再产生新日记文件 |
| P1 | 薄模板（6 行）+ 封存时删空段 + 兼容旧段落 | 1.5 天 | 旧日记打开不乱；新日记无空段 |
| P2 | `digest` + 规则提问 + 卡片式入口 | 3 天 | 无模型也能走完「盘点→填→写」 |
| P3 | 对话式入口：先做 dsh `daily-review` skill（应用内面板留到有需要再做） | 1 天 | 聊完能落一篇，模型不可用退回卡片式 |
| P4 | 回流（反思候选）+ 周复盘读 7 篇 | 2 天 | 封存后 1 条候选进入待确认 |

每期独立可验收，P0/P1 之后就能日常用。

## 12. 风险与反模式

1. **仪表盘化**：数字上首页 → 写日记变冲 KPI。数字只进盘点，不进成长曲线。
2. **AI 代写感受**：感受只能来自你；模型只许整理、改错字、换顺序。
3. **双写**：「每日必做」若还镜像进日记，就有两个写入方。P2 把它挪回工作台。
4. **模型不稳**：所有模型调用都必须有确定性降级，且降级结果也要能直接落盘。
5. **补写**：今天没写，明天不生成「补记」。空着就是空着。

2. **每日必做**：只在工作台。勾选状态改存 `.torch-os/todos/daily.json`，日记文件一个字节都不写。

4. **习惯**：已经在待办事项模块里（2026-10-28 起习惯是 `/api/time/tasks` 上的虚拟任务），
   盘点直接读任务与习惯数据，不再另建一套。
5. **时间预算**：每天 **5–10 分钟**。由此定死三件事：
   - 最多 **3 个问题**，每问 20 字以内，一轮结束，不追问；
   - 开场只给 **3 行盘点**，不复述整篇；
   - 对话式是**主入口**（5–10 分钟刚好够聊），模板式是**兜底**（2 分钟，忙的时候用）。
     两条路都通到同一篇成品，不因为走了哪条而少东西。
