# 导航、本子速度、值班联动与回收中心

日期：2026-11-18。对应本轮五项改进，代码在 Torchos 仓库；个人档案内容留在实际 Vault，不复制到代码仓库。

## 1. 本子打开速度

- 顶部导航统一由一个点击处理器负责，消除一次点击触发两次路由和加载的问题。
- 同一库里打开本子、返回本子列表、切章节复用已加载的总览；只读取目标章节，避免每次重新扫描整库总览。
- 重新进入库以及创建、删除本子后仍刷新总览与章节定义，兼顾 Obsidian 外部改动和恢复后的入口。
- 阅读笔记只等待正文接口。反向链接和关联任务随后加载；补充关联信息时不重建正文 DOM，保留正文选择和阅读状态。
- 连续打开不同笔记或快速切换本子时，以最新请求结果为准。

验收不是宣称固定毫秒数：浏览器测试确认进入本子没有额外 `/overview` 请求；人为挂起反向链接接口，正文仍能打开；关联信息返回后正文节点不变。实际耗时还受磁盘、同步盘、文档数量及正文长度影响。

## 2. 顶部导航

默认顺序：工作台、人生路、自我档案、生活运营、知识库、与神对话、回收中心、设置中心。

- 工作台直接包含任务功能，不再重复提供「待办事项」顶栏按钮。
- 「与神对话」「回收中心」有独立页面和路由，不再挂在工作台内容下方。
- 健康、恋爱不再是顶栏上的两个并列按钮，而是收进「生活运营」的下拉层：鼠标停上去自动展开，点一下进入对应系统；键盘 Tab 到「生活运营」后按 ↓ 展开、Esc 收起并回到按钮。
- 顶栏只高亮「生活运营」这一个入口；当前所在的子系统在下拉层内用 aria-current 标出，展开时才看得到。取消顶栏模式下重复的第二行运营菜单，保留各系统内部导航。
- 点击「生活运营」始终返回运营首页，不再保留上次的健康／恋爱分区；修复点击后看起来没有跳转的问题。
- 「AI 角色与模型」归入设置中心，旧 `roles` 跳转仍兼容；离开角色编辑时保留未保存修改确认。
- 保留自定义导航顺序、选中背景动效和减少动态效果偏好。窄屏横向滚动，缩窄窗口后保持选中入口可见。
- 已同步修订应用内帮助和删除提示中的旧入口。

## 3. 值班 → 列车追踪

- 两个组件共用排班请求，缓存 30 秒；日期使用上海时区。修改排班覆盖项后立即失效缓存并刷新。
- 今天明确休息或不上班时隐藏列车卡片；排班未覆盖、读取失败、未填车次分别显示相应状态。
- 支持 `G1234/3` 等简写及多个车次。优先显示运行中或停站的车次，其次最近即将发车的车次。
- 先显示已有本地时刻表。启用同步的运行模式下，过期或缺失的当天值乘时刻表自动刷新；同日同车失败尝试间隔至少 15 分钟。
- 新车次先按车次号搜索，缺少起止站不会直接阻断；识别失败或存在多个匹配时提示补全起止站。失败保留原数据。
- 保存同步结果时重新读取当前文件并在锁内合并，避免多个页面同步不同车次时丢失另一趟车。
- 弹窗仍可手动关注、导入和同步；关闭后卡片恢复跟随今日值班。

边界：显示的运行状态按时刻表推算，不是实时 GPS 或晚点位置。12306 真实网络可用性未在本轮测试；请求路径、日期、并发保存、识别失败等通过隔离测试验证。QA 模式没有向第三方发出同步请求。

## 4. 回收中心与真实文件统一

问题原因：原回收聚合只包括笔记和任务，遗漏 `.torch-os/本子回收站`，因此文件还在但界面看不到。

- 纳入已有及新增的整本回收批次；提供本子名称、原位置、回收位置、笔记数及大小。
- 支持搜索、类型筛选、选择结果（最多 200 项）、批量恢复和二次确认后的彻底删除。
- 删除内置本子时移动共同父目录，包含根目录附件，避免留下同名空壳；自建本子整体移动。
- 恢复实际移动文件夹回原路径；内置本子同时撤销隐藏标记。原位置已有同名目录时明确拒绝覆盖，保留两边数据。
- 彻底删除只移除已验证的回收批次目录及文件；旧版本留下的空父目录只用 `rmdir` 清理，不删除原位置后来新建的内容。
- 兼容旧版按章节存放的批次；清单缺失时尝试从固定目录结构识别。无法识别的普通批次显示为待检查项目，保留原文件。
- 路径限定在合法回收批次和对应本子内，拒绝链接/重解析点；删除、恢复、清除共享锁，失败尽可能回滚。

这管理的是 Torch 的回收记录，不接管 Windows 回收站。通过文件管理器直接永久删除且未留下回收文件的内容无法凭空找回。

本轮只读核对确认：用户已有「反思复盘」批次存在，记录中为 0 篇，可恢复；没有替用户恢复或彻底删除该批次。
