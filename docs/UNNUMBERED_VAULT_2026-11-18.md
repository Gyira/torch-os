# 数据库业务文件夹取消编号

## 当前规则

四库目录为 `人生路`、`自我档案`、`生活运营`、`知识库`。业务子目录同样使用名称，例如：

```text
人生路/日记
人生路/目标/年度目标
自我档案/档案/基础事实
自我档案/人生导师/记忆
生活运营/待办事项
生活运营/恋爱系统/微信聊天
生活运营/健康系统/每日健康
知识库/收件箱
```

程序里的菜单、本子及档案分类顺序由声明表决定，不再依赖目录名前的数字。删除一个本子后不用给其他目录重新编号。新库和自动补建目录均使用新名称，布局标识为 `pillars-v3-names`。

只取消文件夹的排序前缀。笔记文件名（包括 `00_画像.md`）、日期、文件 ID、隐藏系统根目录不改。历史备份保留原目录结构；回收站内需要恢复的本子目录及恢复清单随之更新。

## 迁移工具与边界

```powershell
# 默认只预览
.\.venv\Scripts\python.exe scripts\unnumber_vault.py --vault "<个人数据库>"
# 停止后端、结束笔记编辑后执行
.\.venv\Scripts\python.exe scripts\unnumber_vault.py --vault "<个人数据库>" --apply
# 需要回退时，先停止服务，并配套还原旧版本程序和插件
.\.venv\Scripts\python.exe scripts\unnumber_vault.py --vault "<个人数据库>" --rollback "<manifest.json>"
```

迁移拒绝符号链接、目录联接和重名覆盖；改名及引用更新前后进行校验。迁移后新增编辑会阻止自动回退，避免覆盖用户内容。中途中断时保留清单，需按清单核对已执行操作，不能盲目再次合并目录。

程序仍能读取旧固定路径形式的笔记链接。若另一个未迁移的库仍有带编号的四库根目录，新后端会明确提示先迁移，不会静默创建一套空库。

重新加载 Obsidian 后使用新桌面插件。其他设备需先完成目录同步，并更新使用固定目录的旧插件；旧版本备份中的编号不代表迁移遗漏。
