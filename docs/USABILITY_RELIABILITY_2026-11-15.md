# 前后端可用性优化 · 2026-11-15

本轮围绕实际发现的请求乱序、重复联网、输入被刷新打断和卡片操作问题展开。延续此前的材质层、组件内设置与黄历可读性改进。

## 已落地的行为

### 任务与通用请求

- 任务列表只接受最近一次刷新结果；较早请求无论成功还是失败，都不能覆盖新列表、版本号或错误提示。当前刷新失败时保留已有任务，仍提示失败。
- `api()` 将调用方取消信号与内部超时组合，清理监听和定时器。主动取消保留 `AbortError`；超时给出核对结果的提示。不会自动重试写请求。
- 超时也覆盖 JSON 响应体读取。成功状态但损坏的 JSON 不再退化为空对象、被误认为操作成功；204 空响应仍兼容。
- 401 保留可供调用方判断的状态码；非 JSON 错误页不会直接渲染到 UI。
- 支持 `Headers` 对象，GET 不再附加无用的 JSON Content-Type；JSON 正文和 FormData 分别保留正确的请求头行为。

取消浏览器请求不代表撤销服务端已经开始执行的工作，尤其不能据此重复提交写操作。

### 天气前端

- 连续输入、清空、添加城市或关闭详情时，取消上一条城市搜索请求；仍保留请求版本检查，避免晚到响应覆盖新查询。
- 天气刷新重画详情时保留当前城市搜索文字、焦点和选区；主动添加城市后的清空逻辑仍生效。
- 中文输入法组字期间不触发在线搜索，确认候选字的 Enter 不会误添加城市。
- 天气、值班和列车卡片以可见内容作为可访问名称，操作说明移至 `aria-description`，避免语音控制读到的名称与画面不一致。
- 拖拽手柄命中宽度由 12px 增至 24px，保持原有布局、方向键排序与跨栏操作。

### 天气后端

- 自动 IP 定位增加 30 分钟缓存，避免已经命中天气缓存仍重复等待定位服务；手动刷新仍可重新定位。
- 相同地点、相同刷新模式的并发请求共用正在执行的结果；失败后清理占位，下次请求可以重试。不同地点的预报请求不会被一把全局网络锁串行化。
- 天气缓存上限 64 个地点，区分同名异地，淘汰最早写入的条目。缓存命中时按当前操作返回定位来源，不把手动选择误标为 IP 定位。
- 出站响应改为流式读取，在解码后数据超过 256,000 字节时停止，不再完整下载后才检查。保留 HTTPS、固定域名、8 秒网络超时、禁止重定向及无自动重试的边界。
- 非对象 JSON、无效编码、损坏 JSON 统一转成可理解的天气服务错误。

## 第二轮：资料包流程与统计显示

- ChatGPT 资料包统一为带固定标题和底部操作区的弹窗，补充移动端布局、已选数量、被筛选隐藏的选项数量、空结果与加载失败重试；重复打开保留当前选择。历史导出时间使用本地可读格式。
- 筛选只影响显示，不使已经确认的正文预览失效。改变勾选才失效预览；预览期间改选时忽略旧结果。
- 弹窗关闭时取消读取请求；关闭重开后，旧选源和旧预览不能写入新会话。历史导出状态单独显示，避免晚到的状态覆盖预览结果。
- 导出时禁用重复提交和修改选源，完成或失败后恢复控制；成功的一次预览不能连续重复导出，失败后重新预览核对再提交。关闭后恢复触发按钮焦点。
- 后端选源改用提前剪枝的目录遍历，在进入微信、备份、隐藏目录和系统目录之前跳过；仍不跟随符号链接和目录联接，每个候选文件继续通过原有安全路径校验。不缓存选源清单，保持外部修改可见。
- 横幅统计、档案完整度和热力图进度条改用数值属性配合 CSSOM 设置宽度，删除受 CSP 拦截的 HTML 内联 style。资料包选源行改用样式类；没有放宽安全策略。
