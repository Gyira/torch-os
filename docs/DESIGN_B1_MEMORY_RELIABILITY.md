## 范围与行为

| 项目 | 改动 | 行为/交互影响 |
| --- | --- | --- |

| 时间线、问答记忆 | 同一规范化文件路径的读取、合并、提交放在同一写入保护范围 | 多线程、多进程请求不再丢失彼此追加的内容 |

## 边界

- 锁约束本机采用此协议的写入进程。Obsidian 等外部编辑器不取锁，提交前的字节检查能检测已经发生的修改，但无法保证外部程序恰好在检查与替换之间写入时的原子比较更新。跨机器同步也不由本机锁协调。
- 本批检查的是写入操作期间的文件版本，不是模型生成开始时的版本；未引入全量整理跨模型调用的事务。
- 全量整理由多个文件步骤组成，仍可能部分成功；失败提示明确说明此前完成的画像/档案步骤保留，不声称整批回滚。
- 强制终止进程可能留下未提交的 `.memory-*.tmp`；其不会被作为 Markdown 记忆加载。本批不做自动清理或历史裁剪。
- 已验证模拟磁盘错误与进程终止；没有进行真实断电、磁盘硬件故障或跨机器测试。

## B1-R：Windows 路径检查与读写协调（2026-11-03）

### 复现与根因

原 `test_threads_keep_all_appends` 在本机 Python 3.12.10 独立运行仍出现 `os.replace` 的 WinError 5。原锁只保护读取/合并/提交，但 `safe_note_path`、目标文件 `Path.resolve()` 在拿锁前已经执行；并行请求的目标文件检查会和正在提交的写入相撞。

隔离实验保持原追加和文件替换实现，只在临时库移除目标文件的锁外探测，连续 10 轮通过。CPython 3.12.10 的 `_getfinalpathname` 使用共享模式为 0 的文件句柄解析路径，与上述观察一致。源码依据：[CPython Windows 路径解析实现](https://github.com/python/cpython/blob/v3.12.10/Modules/posixmodule.c#L4518-L4579)。没有将错误归因于未经验证的杀毒软件或百度同步。

### 最小改动与外部行为

| 文件 | 改动 | 原则与行为 |
| --- | --- | --- |
| `memory_store.py` | 锁键由“规范化父目录 + 文件名”生成；取得线程/进程锁后才进行目标文件安全检查；新增受同一锁保护的读取 | D1/D2。保留原目录越界/链接校验，消除协作调用之间的检查与替换冲突 |
| `mentor_memory.py` | 固定路径先构造、后在锁内校验；核心/时间线/问答读取使用共同协议；核心写入返回本次提交结果 | 不改变目录、内容格式和正常返回字段；避免锁内重复加锁和返回另一轮更新的内容 |
| `self_archive.py` | 仅画像读写接入同一协议；写入结果从本次序列化内容解析 | 画像并发结果与对应提交一致；档案条目替代事务仍留给 B4a |
| `test_memory_reliability.py` | 增加真实读句柄阻塞、检查时机、画像并发结果、越界/链接保护和返回格式测试 | 不放宽旧断言、不更换成虚假成功的文件替换 |

属于已授权 B1 的可靠性修复。正常操作路径与交互习惯不变；没有引入文件替换重试、模型重发、新依赖或数据迁移。冲突仍返回 409，持久化失败仍明确报告。
