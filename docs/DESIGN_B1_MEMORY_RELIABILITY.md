# B1：记忆可靠性实施与验收

日期：2026-11-03。依据用户确认的 D1（记忆是核心资产）、D2（当前档案与成长历史并存），以及已批准的 B1 方案。

## 范围与行为

| 项目 | 改动 | 行为/交互影响 |
| --- | --- | --- |
| 核心记忆、现状画像 | 历史名称追加唯一标识，独占创建；旧内容写入并 flush/fsync 成功后才提交当前版本 | 同秒更新不再互相覆盖历史；备份失败明确终止本次更新 |
| 时间线、问答记忆 | 同一规范化文件路径的读取、合并、提交放在同一写入保护范围 | 多线程、多进程请求不再丢失彼此追加的内容 |
| 初始化 | 与正常写入使用相同锁；只在文件不存在时创建；传递只读模式 | 初始化不会覆盖另一个请求刚写入的记忆 |
| 外部编辑 | 提交前对比最初读取的原始字节 | 检测到变化返回冲突，不用旧内容覆盖；不自动重试 |
| 损坏资料 | 追加前严格解析原始编码和 YAML | 不再把无法读取的文件当空文件重建 |
| 失败反馈 | 全量整理上抛记忆错误；聊天返回 memory_errors，前端保留回复并显示记忆保存失败 | 区分“回复成功”和“记忆保存成功”；不把失败当作零条更新 |

分类为 **B 类**：改变错误和并发情况下的外部行为；没有改变日常操作习惯、AI 审核规则或目录归属。无新依赖、无数据迁移，未操作真实个人资料。

## 实现位置

- `backend/app/memory_store.py`：本批限定的写入辅助层；进程内线程锁 + Windows 字节范围锁 / POSIX flock；锁文件置于系统临时目录的 `torch-os-memory-locks`，不占用个人资料目录。
- `backend/app/mentor_memory.py`：核心记忆、时间线、问答、初始化接入；Markdown 内容结构保持兼容。
- `backend/app/self_archive.py`：仅现状画像写入接入。条目替代等其他写入链路留待独立审查。
- `backend/app/self_synthesize.py`：传递只读参数，记忆失败不再静默吞掉。
- `backend/app/ai_roles.py`、`frontend/mentor.js`：传递并显示记忆保存错误，保留已收到的聊天回复。
- `scripts/test_memory_reliability.py`：13 项独立临时资料测试。
- `scripts/test_ui_polish.mjs`：新增“回复成功但记忆失败”的反馈测试，当前合计 16 项。
- `scripts/check_all.ps1`：接入记忆可靠性回归。

核心记忆和画像写入结果新增 `history_path`，指向本次旧版本的相对路径；首次创建为空字符串。原有返回字段不变。

## 边界

- 锁约束本机采用此协议的写入进程。Obsidian 等外部编辑器不取锁，提交前的字节检查能检测已经发生的修改，但无法保证外部程序恰好在检查与替换之间写入时的原子比较更新。跨机器同步也不由本机锁协调。
- 本批检查的是写入操作期间的文件版本，不是模型生成开始时的版本；未引入全量整理跨模型调用的事务。
- 全量整理由多个文件步骤组成，仍可能部分成功；失败提示明确说明此前完成的画像/档案步骤保留，不声称整批回滚。
- 强制终止进程可能留下未提交的 `.memory-*.tmp`；其不会被作为 Markdown 记忆加载。本批不做自动清理或历史裁剪。
- 已验证模拟磁盘错误与进程终止；没有进行真实断电、磁盘硬件故障或跨机器测试。
