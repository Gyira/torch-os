# B2：导师会话、请求与草稿隔离

日期：2026-11-03。分类：B 类前端交互；对应 D1、D3、D9。

## 问题与实现

`frontend/mentor.js` 原来把打开会话、发送消息、新建会话的结果直接写进共享 state：
A 会话的迟到回复可能写入 B、替换 B 的 `threadId`、解除 B 的 busy 或覆盖状态提示。

本批实现：

1. 每个会话有稳定身份：已有会话用 `thread:<id>`；尚未取得服务端 ID 的新对话用
   `local:<seq>`。切换、新建和离开页面都会推进打开世代。
2. 每个会话独立记录在途请求；A 的迟到成功/失败/finally 只清理 A 的 pending，
   不修改 B 的 busy、消息、线程、输入框或状态提示。
3. 页面级 `openThread` 用世代号防止 A/B 乱序返回；离开导师页调用 `leaveMentor()`，
   使页面级回调失效，但保留服务端历史、页面内草稿和未完成请求。
4. 草稿按会话身份存在内存 Map；失败响应只在输入框仍为空时恢复原文；
   切换回来可以继续原草稿。刷新页面不承诺恢复未持久化草稿。
5. 消息列表只在用户发送或原本接近底部时跟随滚动，不把正在阅读的用户拉到底部。
6. 保持 Enter 发送 / Shift+Enter 换行、中文输入法 `isComposing` 不发送、
   旧忆灵只读和原有 300 秒超时。
7. “等待回复时编辑下一条草稿”没有夹带实施；当前仍禁用输入框。

## 验证

`scripts/test_ui_polish.mjs` 新增覆盖：A→B、A→新会话、A/B 乱序返回、
A 的 finally 不解除 B busy、失败不覆盖后来输入、离开重进恢复草稿、
中文输入法 Enter、滚动不抢位置。全部 27 项通过。

## 回退

只撤回 `frontend/mentor.js`、`frontend/self.js` 的 `leaveMentor` 接线、
`frontend/mentor-model.js`（B4b/B5 文案除外）和对应 UI 测试。
后端历史、记忆文件和数据库不变；不删除服务端会话。
