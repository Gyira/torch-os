# 恢复演练（一键流程）

恢复演练回答一个问题：**现有备份真的能恢复出一份可读、完整、可验证的数据副本吗？**
它不覆盖当前库，不删除任何备份，也不自动把副本切换为当前库。

## 流程

1. 生成一份新的备份 ZIP（路径穿越、哈希清单与 SQLite 完整性在生成时已校验）。
2. 把它恢复到 `data/restored/<32 位十六进制>/` 的独立目录。
3. 只读打开副本自己的数据库，检查完整性、外键与必需表，并统计文件清单。
4. 写一份 Markdown 报告到 `.torch-os/diagnostics/restore-drill-<时间>.md`。

相关接口：

- `POST /api/backups`：创建一份新的本地明文备份。
- `POST /api/backups/drill`：请求体必须是 `{"confirm": true}`，生成备份、恢复副本并验证。
- `GET /api/backups/restored/{name}/verify`：只读验证一份已有恢复副本。
- `GET /api/backups/drill/last.md`：最近一次演练报告。
- `GET /api/backups/drill/reports`：历史演练报告列表。

## 边界

- 演练产物是**恢复副本**，不是当前库；不会覆盖当前库，也不会自动切换。
- 「把副本切换为当前库」需要单独设计、明确确认并保留回滚路径。
- 报告只写文件名、计数与校验结果，不写笔记正文。
- 演练报告只增不减；历史报告可以在设置页逐份下载。
