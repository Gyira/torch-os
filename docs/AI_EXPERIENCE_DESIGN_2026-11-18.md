# Torch AI：角色、模型与个人记忆的连续体验

## 设计判断

你的主要需求是：可以在 ChatGPT 或 Torch 里自然对话，不用反复介绍自己；值得留下的内容回到自己的 Markdown 数据库；专业角色按需要帮助你，而不是要求你维护多套互不相通的背景。

因此采用四层结构：**模型负责回答，角色负责分工，Torch 管理资料与记忆，动作执行负责校验和落盘。**

人生导师仍承担理解近况和延续话题的入口。写作伙伴、学术导师、生活管家等保留为场景助手，其读取范围和允许动作继续由服务端决定。换模型不等于换人格、重建资料或扩大权限。先把单角色对话和知识循环做好，再按可衡量的需求增加协作。

## 本次已实现

### 1. GPT / DeepSeek 切换

入口：**AI 角色 → 对话模型 · GPT / DeepSeek**。

- DeepSeek：沿用现有 dsh 及其模型配置；本次没有另建一套 DeepSeek 凭据。
- GPT：使用 OpenAI 官方 Responses API。填写自己账户可用的模型 ID 和 OpenAI API Key；推理强度可用默认、低、中、高。若模型不支持某参数，明确报错，不偷偷换模型。
- 模型配置按请求开始时取快照，中途修改只影响后续请求。并发请求不会互相改写正在使用的模型选择。
- 同一角色会话继续使用本地历史。生产应用的 dsh 文本回合由服务端重新提供当前资料与有界历史，不依赖旧模型进程里不透明的上下文；GPT 也不传 previous_response_id。
- GPT 请求设置 store=false，不配置工具，不自动把失败请求转发到 DeepSeek。网络错误、配额不足、拒绝访问和输出不完整都有明确反馈，不对失败网络调用自动重试。
- 已有“占位回复补答”机制保留；补答现在携带原始问题和上下文，避免模型只看到“重说一次”。这类补答仍可能增加一次模型调用。
- 模型生成的提议、档案更新和记忆仍经过原有服务端校验；不把模型返回的 JSON 当成已执行动作。未完整生成的 GPT 响应不会进入动作处理。
- 导师/角色的新回复显示模型标记；导师重新打开历史后，也能读取已记录的模型信息。

适用范围是 **RoleService 角色层及其调用方**。“与神对话”主 dsh 界面和单独的日记对话通道尚未改成 GPT 通道；模型设置中的说明明确标出范围。

### 2. 导师更贴近当前问题

检查发现旧实现按顺序消费上下文预算：档案最多 20,000 字、导师记忆最多 13,000 字，后面的日记与任务可能拿不到空间；最近日记又按旧到新排列。

现在为后续来源预留预算，让任务、日记等有机会进入本轮。日记按最新优先排序，避免先截掉今天。每条来源记录实际包含的字数和节选状态，界面不再暗示模型已读完整篇笔记。

近期会话承接从最多 8 条、每条前 1,200 字调整为最多 12 条、合计约 12,000 字，优先保留最近内容。单条过长时保留开头和结尾并标明节选，降低结尾决定被截掉的概率。历史中的助手观点不自动升级为用户事实。

这是确定性的上下文改进，尚不是语义检索或长期会话摘要。没有声称更换提示词就能保证模型回答更聪明。

### 3. ChatGPT 网页版接力

入口：人生导师输入区，以及专业角色抽屉的 **到 ChatGPT 继续聊**。

1. 当前问题、角色允许的背景，以及当前草稿/选文（专业角色入口）组成接力预览。
2. “附带本角色的近期对话节选”默认不勾选。开启后只加入当前角色、当前模式且权限仍有效的历史。
3. 页面显示来源数量、文字量和是否节选。用户检查后点击复制，再打开 ChatGPT 粘贴。
4. 在 ChatGPT 聊完，把分享链接或有价值的正文带回现有 Torch 取回/归档流程。

准备接力内容不调用模型、不上传、不创建新会话、不写记忆。没有应用内 Key 时也可使用。图片没有装进这个文本接力包，界面明确说明；应用内 GPT 图片回合有单独的图片输入适配。

这与“ChatGPT 资料包”的用途不同：资料包用于长期项目背景，接力用于当前问题与近期话题。二者共享本地事实来源，外部聊天内容仍通过取回流程回来，不尝试控制 ChatGPT 网页登录态或自动读取私人会话。

## 配置与数据位置

- 本机模型配置和加密 Key 位于 `%LOCALAPPDATA%/Torch/ai-models`，未配置 LOCALAPPDATA 时使用用户目录下的 `Torch/ai-models`。
- Key 不写入 Vault，不返回给前端，也不在配置状态、测试报告和错误消息中回显。
- 本地采用 AES-GCM 加密，密钥文件同属本机应用目录；这不是操作系统凭据库隔离，也不能防御已能读取该目录的本机攻击者。
- Key 可从界面保存，或使用 `OPENAI_API_KEY` 环境变量。清除本机 Key 不会删除环境变量。
- 设置保存不验证连接、不调用收费模型。模型 ID 由用户账户可用列表决定，没有猜测或硬编码账号可用的 GPT 型号。
- OpenAI API 账户与 ChatGPT 产品使用方式不同；具体费用和额度按 API 账户及其权益确认。没有把 ChatGPT 网页订阅假设成可直接供本应用调用的 Key。
- QA 环境禁用模型配置写入、凭据读取和模型调用。真实主机需要能够访问官方 OpenAI API；未执行真实账号联网验收。

## 验证

- 模型专项：16 项通过，涵盖加密存储、不回显、请求快照、官方端点、无工具、图片格式封装、错误不泄露/不重试、不完整输出、禁用环境、跨模型承接历史、角色权限、只读接力、上下文预算。
- `tests` 主测试集：131 项通过；保留 1 条既有 Starlette/httpx 弃用提示。
- 角色/导师专项回归：103 项通过、2 项跳过，日志 `artifacts/ai-role-regression.log`。
- 前端输入与请求回归：35 项通过。
- 浏览器 76 项检查通过：模型配置读取、编辑时保留草稿、无模型时准备接力、历史主动勾选、320/390px 布局、离线角色入口，以及原有资料包/设置/黄历等。报告与截图在 `artifacts/ai-experience/`，接力弹窗 axe 检查无违规。
- 模块接口检查覆盖 116 个模块。

上述模型响应来自模拟传输或假 runner，没有使用真实 API Key，没有产生模型调用费用。浏览器窄屏模拟不能替代安卓 Obsidian 真机验收；新入口属于主机 Web 前端，Companion 尚未新增原生模型调用界面。

## 后续建议，尚未实施

1. 建立个人问题评测集：用同一批脱敏背景比较 GPT 与 DeepSeek 对“最近变化、纠正旧观点、任务取舍、知识追问”的回答，按引用准确性、纠正遵从、行动可执行性评分。
2. 加入有来源的会话摘要：重点保留用户确认的决定、尚未解决的问题、撤回和纠正；摘要不能覆盖原始会话。不要把 AI 对用户的推测直接变成身份事实。
3. 在角色既有权限内做问题相关检索：先关键词/标题与近期记录，评测证明需要后再加向量检索，避免默认把整个库发给每个模型。
4. 角色协作采用明确的任务交接：例如导师识别知识问题后，带着用户选定的资料交给学术导师；不让所有角色互相广播聊天或无限自动协作。
5. Android 优先延续“笔记 + ChatGPT + 分享取回”的路径。若主机服务远程访问和认证方案明确，再把同样的接力/模型选择能力接入 Companion。
