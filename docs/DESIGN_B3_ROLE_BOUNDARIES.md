## 建议的固定权限映射

路径从 `vault_layout.py` 的常量和 chapter key 推导，不在角色 Markdown 中维护另一份可自由修改的绝对路径。角色名字、风格、提示词和用户自定义 Skill 不扩大后端权限。固定目录的自动补建机制不变。

| 角色 ID | 可读取的业务资料 | 可输出/执行的归属 | 特别约束 |
| --- | --- | --- | --- |
| `mentor` 人生导师 | 四库的个人业务资料、导师记忆与对应业务摘要 | 保留现有档案/导师写入链；未来自主更新仍在这些目录 | 全局读不等于任意跨域写；不把密钥、凭据、运行日志、备份副本批量送进模型 |
| `journal_companion` 写作伙伴 | `00_人生路` 内当前笔记与按需选取的资料 | 人生路内的新建、整理、移动 | 不自动读取身份、恋爱、健康或知识库 |
| `academic_mentor` 学术导师 | `03_知识库`、用户明确提交的分享正文/问题 | 知识库内的新建、整理、移动 | 其他库中的学习经历仍不能自动取用 |
| `health_doctor` 私人医生 | `02_生活运营/02_健康系统` 的健康记录及其受控摘要 | 健康报告、问诊记录等原有健康系统产物 | 不自动补入自我档案、恋爱或财务资料 |
| `health_doctor/estimate` 私人医生的估算模式 | 当前饮食/运动输入；如明确选择资料，只限健康系统 | 返回当前估算结果，沿用健康页现有预览/保存动作 | 用户明确纠正：没有独立“健康估算助手”；旧 ID 只作兼容别名 |
| `finance_advisor` 理财专家 | `02_生活运营/03_财务系统` | 财务报告等原有产物 | 没有财务记录时明确为空，不跨库寻找个人信息 |
| `love_master` 恋爱大师 | `02_生活运营/01_恋爱系统` 七个页面的业务记录和既有摘要 | 恋爱系统内的日志、画像、报告等原有产物 | 保留现有脱敏规则及批量日记的原文用途；新建待办经受控任务动作转交 |
| `life_assistant` 生活管家，推荐方案 | `02_生活运营`：待办、恋爱、健康、财务、家庭 | 生活运营内与原有模式相符的任务/生活建议等动作 | 这是父模块管理角色；不再默认读取自我档案或人生路。各专业角色仍只读各自子目录 |
| `yiling` 旧忆灵 | 原会话/记录供用户查看 | 不发起新的模型推理，不新增身份修改 | 不授予第二份全局角色权限；旧综合接口需明确兼容或提示转入导师 |

这里的“可读取”是授权上限，不代表每次请求加载整个目录。默认上下文继续使用短摘要、当前笔记和现有字符预算。内嵌业务数据库通过对应模块的查询器读取，不把整库文件交给模型。历史文件只在明确查看历史等场景取用，避免旧判断默认污染当前判断。

## 已确认的取舍

### 1. 生活管家的范围

**推荐：生活运营父模块。** 允许其整合生活运营内的健康、财务、恋爱与待办摘要，取消自我档案身份注入。

- 现状 → 建议：生活运营资料加全局身份 → 仅所属生活运营父目录。
- 理由/收益：对应 D4/D5；保留已有综合生活建议能力，同时区分它与人生导师。
- 风险：父模块管家仍会接触各生活子系统摘要，应明确写在角色说明中。
- 迁移成本：低至中；旧会话重新建立模型上下文，身份相关回答不再从档案自动补齐。
- 回退：恢复旧政策可恢复此前能力，但会重新扩大资料范围，不作为失败时的自动降级。
- 备选：只允许待办与家庭系统。边界更窄，但健康/财务/恋爱综合建议会被取消或移给人生导师；影响较大，不默认采用。

### 2. 跨域待办、习惯与记忆事件

**推荐：由 DSH 调度受控动作，领域角色不获得对方目录权限。**

- 现状 → 建议：恋爱角色能提出待办、生活管家能提出习惯 → 保留用户操作入口，由现有后端任务/习惯服务作为受控执行器完成目标领域写入。
- 对应 D4/D8/D9；不增加一次模型调用，也不让用户去另一个页面手动重填。
- 任务动作只传必要的标题、日期、优先级等业务字段，不接受文件路径、不提供任务库任意读写；返回本次任务标识和结果。
- 习惯现存于 `00_人生路/04_目标/04_习惯追踪`。生活管家经固定“习惯摘要/创建习惯”能力操作，作为显式跨域能力登记，不因此开放整个人生路。
- 记忆事件允许领域角色以自身身份单向投递；来源引用须属于该角色可读范围。投递不等于写入自我档案，不可读回其他角色事件。
- 本批沿用各入口现有的采纳/自动触发方式，不新增确认弹窗；扩大自主执行范围留给后续明确批次。
- 风险：若只给动作加一个标签却不限制执行参数，仍会绕过领域边界。必须在合并 edits 后验证目标。
- 迁移成本：中；旧待处理提案在执行时重验，新建待办交互不变。
- 回退：撤回动作分发接线与权限校验，保留已创建业务数据；不删除待办或习惯来回退代码。

### 3. 旧会话与旧忆灵

**推荐：历史仍可见，权限变更后的模型从干净上下文继续。旧忆灵不再新推理。**

- 同一前端 thread 可以继续显示旧消息；第一次使用新权限时提示：“历史对话保留，从这一轮起按新的资料范围继续。”
- 新建 dsh 模型会话；不沿用旧 dsh_session_id，也不把切换前的最近 8 轮或它们的摘要重新注入。
- 持久化 `policy_version`、`scope_fingerprint`、`context_start_turn`，后续只使用此起点后的允许上下文。角色、资料范围或获准动作变化时重新切换。
- 已发送请求携带政策版本，完成时重验；旧请求不能把旧模型 session 写回新政策线程，也不能执行已失效权限下的输出。
- 迁移成本：中；用户可能需要重述旧对话中的某个问题。不能声称“旧内容已从模型记忆删除”，只能保证新运行不复用旧上下文。
- 旧忆灵会话只读；旧综合 API 返回可识别的兼容提示及导师入口，不默默换用新 JSON 协议，也不删除旧角色文件。依赖旧接口的客户端需要适配。
- 回退保留新元数据和所有历史。旧代码可忽略附加表；切回旧政策会恢复旧范围，必须是显式操作。

## 执行边界与交互规格

1. 服务端先解析 role/mode/entry，再构造固定 policy。未知角色/模式继续沿用现有错误类型。
2. 所有 selector 必须在真正打开文件或查询业务表之前获准；非法范围返回 403 和稳定错误码 `role_scope_denied`，模型未调用、资料未读取。不先读取后过滤。
3. 校验规范化后的真实路径；阻止 `..`、绝对路径、大小写/前缀相似目录、符号链接和目录联接越界；仅字符串 startswith 不足以判断归属。
4. recent_notes、ops_summary、引用和缓存同样受限。缓存以当前库、角色、scope fingerprint 为键；不复用全局摘要后再截断。
5. `run`、`run_once`、chat 及报告专用入口共用同一政策。服务端预组装资料必须由受控 builder 产生，带真实来源集合；浏览器不能提交一个“已授权”的标记。
6. 区分“用户主动输入的文字”和“应用自动附加的资料”。用户主动输入可直接交给当前角色；不能可靠推断文字原来来自哪个库，也不做文字内容审查。已保存笔记/自动选区应绑定获准的来源路径，未保存草稿明确标作用户提交内容，不赋予额外检索权。仅客户端提供的来源标签不是授权证明。
7. 模型返回的路径、章节和动作都是待验证数据。移动笔记需同时校验旧路径与新章节；最终参数以合并 edits 后的值为准。
8. 错误只在当前操作处提示，保留输入与草稿。正常成功流程不多弹窗、不抢焦点，不重排恋爱/待办页面。当前轮能读取的来源仍可查看。
9. 导师读取权限为全局业务资料，但按需检索和预算截断仍保留；全局权限不意味着本批已经实现所有信息的自动检索能力。

## 整体伪代码（读取已实施；输出动作校验属于 B3-2）

```text
policy = fixed_policy(role_id, mode, entry, vault_identity)
request = classify_user_input_and_app_sources(payload)
policy.validate_selectors_before_read(request.selectors)
context = scoped_builder(policy).read(request.app_sources)
thread = rotate_model_context_if_scope_changed(thread, policy.fingerprint)
history = load_turns_since(thread.context_start_turn)
result = model(context, history, request.user_input, thread.new_or_valid_session)

assert_current_policy(thread, policy.fingerprint)
for output in result.outputs:
    final_payload = merge_allowed_edits(output)
    action = resolve_server_owned_action(output.kind)
    policy.validate_action_and_paths(action, final_payload)
    dispatch_with_existing_trigger_rules(action, final_payload)
```

模型调用期间不保持长时间 SQLite 事务。线程政策切换与模型 session 更新使用短事务/版本比较，避免并发迟到响应撤销新范围。
