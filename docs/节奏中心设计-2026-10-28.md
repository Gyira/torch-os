# 节奏中心（Ritual Engine）设计 · v1

> 2026-10-28 · 起因：功能越加越多，但没有一条线把它们串起来；
> 想做一个侧边栏「引导建议卡」，每天推差异化的建议。本文回答三件事：
> **为什么现在的做法会变成 37 个闹钟**、**该用什么模型串**、**先做哪一块**。

## 0. 一句话

不要给 37 个章节配 37 个提醒，也不要再建一个任务系统。
**每天 3 个卡位、每周 1 次复盘、每月 1 次开通**——其余一律不催。

## 1. 先看现实：37 个章节，31 个一次都没用过

2026-10-28 实测（只读扫描四库）：

| 有内容的章节 | 篇数 | 最后一次 |
|---|---|---|
| 任务与待办 | 7 | 10-27 |
| 项目计划 | 2 | 10-22 |
| 通用方法 | 2 | 10-22 |
| 我的八字参考 | 2 | 10-28 |
| 记忆与自传 | 1 | 10-27 |
| 内核与三观 | 1 | 10-27 |
| **其余 31 章** | **0** | — |

日记刚清零；反思、心得、周复盘、月度目标、知识库、情感记忆——**全是空的**。

这个数字说明的不是「功能没被利用」，而是：**货架搭好了，货还没生产出来。**
给 31 个空货架各配一条提醒，只会得到 31 条焦虑——这正是你现在觉得"太复杂"的来源。

## 2. 三个判断

**判断一：空章节不配拥有提醒权。**
一个章节有内容、且你用过，才进入节奏；空章节只在「月度开通」里出现一次，而且是邀请，不是催办。
理由：提醒的价值取决于「点进去有东西可做」。空章节点进去只有一张白纸，等于把焦虑外包给界面。

**判断二：侧边栏卡片是渲染器，不是模型。**
先有「节奏模型」（什么该在什么时候出现、为什么是今天），再谈卡片长什么样。
反过来先做卡片，就会退化成一张"你今天还没做的事"清单——和每日必做没区别。

**判断三：别再建一个任务系统。**
任务系统解决「要做的事」，环节解决「要记的事」。两套待办放一起，你会开始逃避第二套。
事务（任务/每日必做）留在现有模块，环节只负责记录与复盘。

## 3. 模型：三圈 + 三个卡位

### 三圈（按频率，不按功能）

| 圈 | 章节 | 出现频率 | 出现在哪 |
|---|---|---|---|
| **内圈** | 日记 · 任务 · 每日必做 · 反思 · 周复盘 | 每天 / 每周 | 侧边栏卡片，每天 3 条 |
| **中圈** | 心得 · 目标 · 项目 · 知识库收件箱 · 情感记忆 | 每两周 / 每月 | 周复盘里带过，不单独提醒 |
| **外圈** | 其余 27 章 | 按需 | 每月「开通 / 大扫除」一次，最多提 3 个 |

内圈是"每天真的会发生"的；中圈是"需要一点时间才有的"；外圈是"还没开始"的。
**不同圈层用不同界面**，是这套设计最重要的一条——它们不该长在同一张卡上。

### 三个卡位（每天 3 条，不再多）

1. **固定位**：今天的环节本体（日记 / 今晚 8 分钟）；
2. **到期位**：内圈里最该出现的那一条（任务逾期、习惯连续未打、反思超期）；
3. **沉默位**：中圈里最久没动的一章（两周一次，不每天出现）。

选位规则（确定性，先不调模型）：

```
候选 = 所有「有货」的内圈章节 + 本周轮到的一个中圈章节
排序 = 权重 × 超期天数，同分按章节固定顺序
取前 3；今天点过「跳过」的，14 天内不再出现
```

### 卡片长这样

```text
┌──────────────────────────────┐
│ 今晚 8 分钟              21:30│
├──────────────────────────────┤
│ ● 日记      今天还没写        →│
│ ○ 背单词    逾期 6 天：做/推/删→│
│ ○ 反思      11 天没记，上次是…→│
├──────────────────────────────┤
│ 本周 2/3          [今天跳过]  │
└──────────────────────────────┘
```

规矩：

- 每条必须写**为什么是今天**（"逾期 6 天""11 天没记"），不写形容词；
- 每条只有一个动作，点进去就是那个环节，不是跳到一个模块首页；
- 不显示分数、连续天数、红色叉；「跳过」不累积、不补做；
- 第 4 条起进「更多」，默认折叠；卡片高度固定，不做无限滚动。

## 4. 差异化建议怎么算

| 触发 | 建议一句话 | 点进去做什么 |
|---|---|---|
| 今天没有日记 | 「今天 3 条线索，8 分钟」 | 日记闭环（已做好） |
| 任务逾期 ≥ 3 天 | 「背单词逾期 6 天：做、推、还是拿掉？」 | 任务详情，三个按钮 |
| 习惯连续 3 天未打卡 | 「是没顾上，还是这个习惯不现实？」 | 习惯卡 |
| 反思 ≥ 7 天没有 | 「上周那件值班的事，值得复盘一次」 | 反思编辑器（带 3 个问题） |
| 周复盘没写且今天是周日 | 「把这 7 天的日记过一遍」 | 周复盘环节 |
| 中圈章节 ≥ 14 天没动 | 「心得停了两周，一句话也算」 | 对应章节的"写一条" |
| 目标 30 天没动 | 「这个目标还算数吗？」 | 目标笔记 |
| 外圈章节（月度） | 「要不要这个月开始记读书笔记？」 | 开通向导 |

模型的位置：**只负责把选出来的 3 条改写成你的人话**，不负责选哪 3 条。
选择权在规则手里，人格在模型手里——这样它不会每天给你端来一盘"你做得不够好"。

## 5. 让空货架长出东西：产出入库

这是整套设计里最容易被忽略、但最关键的一环。
提醒不能生产内容；**日记和复盘能**。

每篇日记写完，做一次"入库"：

1. 把正文切成 3–5 段；
2. 判断每段属于哪一类：反思 / 心得 / 原则 / 只是记录；
3. 给你 1–3 张候选卡：「这段像一条反思，存到 `02_反思复盘/01_反思`？」
4. 你点确认才写；不确认就留在日记里。

周复盘 = 读 7 篇日记 + 7 次入库结果 → 1 条反思 + 1 条心得 + 下周一件大事。

这样 31 个空章节不是靠"提醒"被填满的，是靠**你已经写下的东西**流过去的。
一篇日记最多点亮一个章节，一个月就能点亮 4–6 个——够用了。

## 6. 归属：谁生产、谁保管、谁提醒

| 模块 | 生产什么 | 保管在哪 | 谁提醒 |
|---|---|---|---|
| 工作台 · 任务 | 事务 | `08_任务与待办` | 节奏中心（到期位） |
| 工作台 · 每日必做 | 打卡状态 | `.torch-os/todos/daily.json` | 节奏中心（到期位） |
| 人生路 · 日记 | 事实 + 感受 | `01_日记` | 节奏中心（固定位） |
| 人生路 · 反思/心得 | 提炼 | `02_反思复盘`、`03_心得体会` | 周复盘环节 |
| 自我档案 · 主动提问 | 关于我的事实 | 身份卡 / 记忆 | 节奏中心（每周 1 问，低频） |
| 知识库 · 收件箱 | 待归类 | `03_知识库/00_收件箱` | 月度开通 |
| 生活运营 · 关系记忆 | 事件 | `05_情感与记忆` | 周复盘环节 |

原则：**一个章节只有一个提醒来源**。现在每个模块各弹各的，是"四个管家"；要的是"一个管家，四个房间"。

## 7. 分期

| 期 | 内容 | 工期 | 验收 |
|---|---|---|---|
| P1 | `cadence.py` + `GET /api/cadence/today` + 侧边栏卡片（只读 3 条，点击跳转） | 3 天 | 每天恰好 3 条，每条都能说出"为什么今天" |
| P2 | 卡片接日记闭环（固定位点进去就是昨晚那个面板） | 1 天 | 从卡片到写完 ≤ 10 分钟 |
| P3 | 产出入库（日记 → 反思/心得候选，确认后落库） | 2 天 | 一周至少点亮 2 个空章节 |
| P4 | 周复盘环节 + 月度开通 | 3 天 | 周日 20 分钟能出 1 条反思 |

先做 P1+P2：一周内可用，而且**不新增任何写入面**。

## 8. 不做什么

- 不做"每日必做 20 项"式的清单；
- 不给每个模块加提醒（一个章节一个主人）；
- 不做分数、等级、连续天数；
- 不对外圈做每日提醒；
- 不在 P1 调模型（规则先跑一周，看哪条真被点开，再谈个性化）。
