# 云端完整备份（2026-11-02）

目标：电脑损坏或换机时，能从网盘拿回**整个个人数据库**，包括四库 Markdown、
微信聊天数据库与媒体、恋爱系统数据库、相册、配置和 `.torch-os`。

它和「设置 → 本地备份」不同：本地备份 ZIP 只包含 Markdown 与主库快照，适合快速
验证恢复；云端完整备份包含整个库，文件会大很多。

## 怎么开启

1. 安装并登录百度网盘 / 阿里云盘 / OneDrive / 坚果云等客户端，创建一个**同步文件夹**，
   例如 `D:\BaiduSyncdisk\薪火OS备份`。
2. 打开薪火OS → 设置 → 备份与恢复 → **云端完整备份**。
3. 填写这个同步文件夹的完整路径。
4. 选择自动备份频率（仅手动 / 每天 / 每周）和保留份数（1–30）。
5. 设置至少 8 位备份密码。推荐保持「用密码加密」。
6. 点「立即完整备份」测试一次；完成后网盘客户端会自动上传。

网盘客户端只会看到最终文件名：

- 未加密：`torch-os-full-YYYYMMDDTHHMMSSffffffZ-xxxxxxxx.zip`
- 加密：`torch-os-full-YYYYMMDDTHHMMSSffffffZ-xxxxxxxx.zip.enc`

生成过程中会在网盘文件夹里短暂出现点号开头的 `.partial` 临时文件；多数客户端会忽略或稍后同步，
完成后才原子改名为正式文件。若网盘里出现 `.partial` 残留，可以直接删除。

## 备份里有什么

- 当前个人数据库下的普通文件（Markdown、图片、视频、语音、Excel、JSON 等）。
- 所有 SQLite 数据库通过 SQLite 在线备份 API 做一致快照：即使微信同步正在写
  `chat.db`（WAL 模式），也不会拿到半份数据库。
- `.torch-os` 里的配置、密钥、任务布局、恋爱迁移数据等。
- `manifest.json`：格式版本、创建时间、逐文件大小与 SHA-256、跳过项警告。

会排除：

- `.torch-os/backups` 和 `.torch-os/restored`（旧备份/恢复副本，避免套娃）
- `.torch-os/logs`、`.torch-os/diagnostics`（日志与诊断，不属于个人数据）
- `.torch-os/cloud-backup-staging`（本次快照的临时目录）
- `.git`、`__pycache__`、`node_modules`
- 数据库旁边的 `-wal` / `-shm` / `-journal` 文件（数据库快照已经包含已提交内容）

## 加密与密码

- 加密算法：scrypt 派生密钥 + AES-256-GCM，按 4MB 分块流式加密；密码错误或文件被
  改动会在解密时被发现。
- 密码不会以明文写入库文件；Windows 使用当前用户的 DPAPI 保护已保存密码，以便
  自动备份继续运行。
- **忘记密码就无法恢复加密备份**。请把密码单独保存在密码管理器或纸上。
- 如果关闭加密，任何能访问网盘文件的人都能看到完整聊天、相册和配置。

## 自动备份

后端运行时每分钟检查一次是否到点；每天/每周只跑一次。备份在线程里执行，页面可以
切走。若上次失败，会自动重试；设置页会显示失败原因。

注意：自动备份需要电脑开机且薪火OS 后端在运行。关机期间不会补跑，下一次打开后如果
已过期会补一次。

## 恢复（重要）

完整备份包含正在使用的数据库，**不能直接覆盖正在运行的库**。请按顺序：

1. 完全退出 Obsidian 和薪火OS 后端（确认 9168/8765 没有进程）。
2. 把当前个人数据库改名备份，例如 `个人数据库-旧`。
3. 用仓库脚本恢复到一个新目录：

   ```powershell
   .\.venv\Scripts\python.exe scripts\restore_full_backup.py `
     "D:\BaiduSyncdisk\薪火OS备份\torch-os-full-....zip.enc" `
     "D:\恢复的薪火OS"
   ```

   脚本会提示输入密码，校验 manifest 和每个文件的 SHA-256，并拒绝覆盖非空目录。
4. 把 `D:\恢复的薪火OS\vault` 里的内容放回个人数据库路径（或把 `.env` 的
   `VAULT_DIR` 指向 `D:\恢复的薪火OS\vault`）。
5. 重新打开 Obsidian。若换了电脑，`.torch-os/cloud-backup.secret` 里的密码可能
   因 DPAPI 机器绑定而无法读取，重新设置一次备份密码即可；旧备份仍可用原密码恢复。

没有密码的 `.zip` 可以先用 `--list` 只看清单：

```powershell
.\.venv\Scripts\python.exe scripts\restore_full_backup.py archive.zip target --list
```

## 网盘选择建议

- **百度网盘 / 阿里云盘**：适合“本机生成完整 ZIP，客户端单向上传”。
- **OneDrive / 坚果云**：同样可用；如果开启“按需下载/选择性同步”，确保备份文件夹
  设置为始终保留在本机，否则后端写不进去。
- **不要**把正在运行的整个个人数据库直接设为双向实时同步：SQLite 的 WAL 和锁文件
  在云盘同步过程中可能造成不完整副本。云端完整备份是**单向快照**，不是实时协作。
