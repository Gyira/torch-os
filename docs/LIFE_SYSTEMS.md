# 生活运营系统（v1.0 P4）

> 生活运营 = 恋爱 / 健康 / 理财 / 家庭。v1.0 只把已有数据和 AI 角色接通；
> 健康、理财、家庭不做完整业务系统。

## 1. 总览

- 只读来源：健康系统的每日记录/身体档案/检验摘要（`02_生活运营/02_健康系统`）、
  `02_生活运营/08_财富与记账` 月度表；恋爱系统自己的只读摘要（不读原始聊天）；
  工作台未完成任务与今日习惯。
- AI 角色：
  - `life_assistant`（总览/建议）→ `05_生活建议`
  - `health_doctor`（健康报告/建议）→ `02_健康系统/00_健康报告`
  - `finance_advisor`（财务报告）→ `04_财务报告`
  - `love_master`（恋爱建议）→ `05_生活建议`
- 报告由用户确认后生成；建议里的任务/习惯只生成 `ai_proposals`，采纳后才创建。
- **不改**健康每日记录/财务月度表；**不**替恋爱系统发消息；**不**控制任何家庭设备。

## 2. 健康系统（2026-11-01 v3）

- 原生二级分区：生活运营 →「健康系统」，与「恋爱系统」平级；七个页面与详细口径见
  [`HEALTH_SYSTEM.md`](HEALTH_SYSTEM.md)。
- 数据全部在 `02_生活运营/02_健康系统/`：`00_健康报告`、`01_每日健康`、
  `02_身体档案`、`03_体检与检验`、`04_训练记录`、`05_问诊记录`。生活运营不再有独立的
  `03_体检与医疗`；旧文件启动时并入 `03_体检与检验`。
- 旧 `01_健康与体重/YYYY-MM.md` 只读兼容，不再写入。
- 私人医生：页内问诊（`advice`），每次问答自动追加到 `05_问诊记录` 当天文档；
  `POST /api/health/report` 基于最近 30 天 + 最新档案生成 `YYYY-MM-DD 健康报告`，
  存固定本子；报告 `memory: false`。
- 未做：训练计划、体检报告 PDF/OCR、CSV 批量导入、进度照片、Web 提醒。

## 3. 理财系统（当前能力）

- 数据：`02_生活运营/08_财富与记账/YYYY-MM.md` 月度表
  （日期/类型/金额/分类/账户/备注）。
- 仪表盘/汇总：`structured_notes.summary`；收入/支出/结余与主要分类由代码计算。
- 理财专家：`POST /api/ops/ai/report {domain:"finance", confirm:true}`；
  报告写 `04_财务报告`；不做投资建议、不推荐具体产品。
- 未做：账户余额、预算、负债、投资明细、账单导入；后续版本再做。

## 4. 家庭系统（占位）

- `02_生活运营/06_家庭与智能家居` 是占位章节；
- v1.0 只展示“后续版本”空状态，不发起任何设备/网络请求；
- 未来方向：家庭物资库存表、智能家居控制面板；需要单独的安全与权限设计，
  不在 v1.0 范围内。

## 5. 恋爱系统 v2（2026-11-01）

- 七个页面：恋爱记忆、微信聊天、排班日历、经期关怀、恋爱相册、八字合婚、恋爱大师；
  全部私人数据在 `02_生活运营/01_恋爱系统/`，按页面分目录；旧 `.torch-os/love/`
  首次启动自动迁移并保留原文件。
- **恋爱记忆**：Markdown 本子 + 现有编辑器；默认「恋爱日志」不可删，AI 补日记先写
  「AI 草稿」；导出 TXT，删除进笔记回收站。
- **微信聊天**：只绑定一个单聊；三态日历（无聊天/已同步/未同步）+ 按日查看 + 媒体 +
  TXT/JSON 导出；只访问 `127.0.0.1` 的 WeFlow API，Token 加密存放在
  `02_微信聊天/.credentials.json`。WeFlow 组件 101/到期用开源
  [olansoft/weflow-wcdb-api-oss](https://github.com/olansoft/weflow-wcdb-api-oss)
  构建的 DLL 替换；不修改闭源 DLL，设置里可备份/替换/回滚。
- **排班日历**：Excel 底表 + `overrides.json` 单日覆盖（上班/休息/车次/备注），可撤销。
- **经期关怀**：仍纯本地计算；数据在 `04_经期关怀/cycle.db`，不接外部服务；
  预测不是诊断，也不能作为避孕依据。恋爱大师只发送阶段/预计日期等聚合信息。
- **恋爱相册**：照片/视频复制进 `05_恋爱相册/`，每个文件属于一个相簿；缩略图、全览、
  移动与删除；`albums.db` 只存元数据。
- **八字合婚**：男女双方出生信息 + 可选四柱；四柱/十神/藏干/大运由本地
  `lunar_python` 或用户手填决定；AI 只写格局、喜忌与合婚解读。结果存
  `06_八字合婚/bazi.db`，历史可切换、删除、导出 HTML。
- **恋爱大师**：关系总览 + 数据看板 + dsh skill 卡片（画像/深度分析/报告/补日记/八字）；
  右侧角色层是唯一聊天入口。所有 AI 走 dsh `love_master` 角色与 `love-master` skill，
  上下文来自 `01_恋爱系统/`；聊天原文脱敏后发送，经期只发聚合阶段。
- 报告/建议仍可写 `05_生活建议`，但恋爱系统自己的产物写 `07_恋爱大师/analysis.db`；
  不再保留独立 DeepSeek Key。

## 6. API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/ops/ai/overview` | 健康/财务/恋爱摘要、最近报告、未完成任务 |
| POST | `/api/ops/ai/report` | `{domain, confirm:true}`；生成并保存报告 |
| GET | `/api/ops/{dataset}/summary` | 既有只读月度汇总（health/finance；health 旧表只读兜底） |
| GET | `/api/ops/{dataset}/months/{month}` | 既有只读月度表 |

健康系统自己的记录/趋势/洞察/报告接口见 [`HEALTH_SYSTEM.md`](HEALTH_SYSTEM.md) 第 4 节。

## 7. 边界

- 报告是参考，不是诊断/投资建议；健康异常建议线下就医；
- 报告/建议 `memory: false`，不进入记忆候选，避免 AI 结论自我循环；
- AI 不可用时返回 409/503，原有月度表与仪表盘不受影响；
- 家庭占位页不包含任何设备控制代码。
