## 3. 恢复 Vault 与数据库

### 3.1 从 U 盘复制到新电脑

建议放到：

```text
D:\torch-data\个人数据库
```

复制命令：

```powershell
robocopy "E:\torch-handoff\个人数据库" "D:\torch-data\个人数据库" /E /COPY:DAT
```

确认关键文件存在：

```text
D:\torch-data\个人数据库\.torch-os\torch_os.sqlite3
D:\torch-data\个人数据库\00_人生路\01_日记\2026-10-21.md
D:\torch-data\个人数据库\03_知识库\00_收件箱
```

### 3.2 修改 `.env`

打开仓库根目录的 `.env`，把路径改成新机器上的实际路径。最小可用配置：

```dotenv
APP_ENV=development
HOST=127.0.0.1
PORT=8765
ALLOW_REMOTE_API=false
API_TOKEN=
DATA_DIR=D:\torch-data\个人数据库\.torch-os
VAULT_DIR=D:\torch-data\个人数据库
VAULT_READ_ONLY=0
MODEL_PROVIDER=local
MODEL_BASE_URL=
MODEL_NAME=
MODEL_API_KEY=
MODEL_TIMEOUT_SECONDS=45
EMBEDDING_PROVIDER=hash
OLLAMA_BASE_URL=http://127.0.0.1:11434
OLLAMA_EMBED_MODEL=bge-m3
```

关键点：

- `DATA_DIR` 指向 **Vault 内的 `.torch-os`**，这样数据库、备份、迁移日志和滴答凭据都在同一个地方。
- `VAULT_DIR` 指向 Vault 根目录。
- `VAULT_READ_ONLY=0` 允许四库写入；改成 `1` 就是只读模式。
- `MODEL_PROVIDER=local` 时不需要云端 Key；要测试管家云端问答再填。
- `EMBEDDING_PROVIDER=hash` 是离线兜底，不依赖 Ollama。

> 旧电脑的 `.env` 当前写的是 `DATA_DIR=./data`、`VAULT_DIR=./data/vault`，那是旧工作区。新机器不要照抄。

### 3.3 两种运行模式

| 模式 | 数据位置 | 启动方式 |
|---|---|---|
| 浏览器模式 | 由 `.env` 的 `DATA_DIR`/`VAULT_DIR` 决定 | `scripts\start.ps1` → `http://127.0.0.1:8765` |
| Obsidian 插件模式 | 当前库 + 当前库`.torch-os` | 插件自动拉后端，端口从 9168 起 |

两种模式可以同时运行，互不影响。  
如果你明天主要用浏览器，按上面的 `.env` 配好即可；如果主要用 Obsidian，复制整个 Vault 后重新安装插件。  
即使主要用 Obsidian，也建议保留一份正确的 `.env`：`check_handoff.py` 和 8765 浏览器模式都会用它。

### 3.4 安装 Obsidian 插件（可选）

1. 先用 Obsidian 打开复制过来的 Vault（有 `.obsidian` 的那一层）。
2. 重新运行 `安装.cmd`，勾选「把工作台装进 Obsidian」，选择这个 Vault。
3. 完全重启 Obsidian。
4. 左侧 ribbon 出现「薪火OS」，或在命令面板搜索「打开工作台」。

插件会优先使用当前库的 `.torch-os/torch_os.sqlite3`，所以复制整个 Vault 后数据是一致的。  
如果插件设置里还留着旧电脑的仓库路径，重新运行安装器或到插件设置里改成本机仓库路径。

## 10. 常见问题

### 页面打开是空的 / 四库没有内容

检查 `.env` 的 `VAULT_DIR` 是否指向复制后的 `个人数据库`，而不是 `torch-os\data\vault`。

### 任务和滴答映射变少了

用错数据库了。把 `DATA_DIR` 指向：

```text
D:\torch-data\个人数据库\.torch-os
```

并确认其中的 `torch_os.sqlite3` 计数是 `documents=6`、`dida_task_links=47`。

### 四库写入提示只读

`.env` 里把：

```dotenv
VAULT_READ_ONLY=0
```

改完重启服务。

### 滴答不同步

确认 `DATA_DIR` 或 Vault 的 `.torch-os` 里有 `dida-credentials.json`；没有就重新登录滴答。不要把凭据内容打印到终端或提交。

### 云端模型不可用

`.env` 默认 `MODEL_PROVIDER=local`，不需要 Key。要用云端时再填 `MODEL_BASE_URL`、`MODEL_NAME`、`MODEL_API_KEY`；管家问答默认仍是本地检索，勾选后才外发。

### 端口被占用

改 `.env` 的 `PORT`（例如 `8766`），或关掉旧的 Python 进程。Obsidian 插件会自己从 9168 起找空闲端口，不受影响。

### 前端测试提示 `document is not defined`

确认使用了 `--experimental-vm-modules`；新增的 `pillar-markdown.test.mjs` 需要这个参数。
